# 升级清单与用户文件保护

## 文件归属

`release_manifest.json` 的 `program_files` 保存文件级完整相对路径，例如 `engine/main.py` 和 `scripts/install.py`。打包过程随源码资产生成清单，升级以旧持久化清单识别受管文件。

备份中的文件集合仅用于恢复。将备份扫描结果或顶层目录名视作受管清单，会把用户自建文件混入升级范围。

## 落地与删除

| 目标状态 | 处理 |
| --- | --- |
| 目标文件尚不存在 | 新增文件并按需创建父目录 |
| 目标已存在且属于旧清单 | 更新受管文件 |
| 目标已存在且属于用户文件 | 保留并报告冲突路径 |
| 文件属于旧清单且新版已移除 | 按文件删除 |

目录作为文件的父路径管理。旧环境缺少可靠清单时中止升级，经可核验迁移建立归属依据后再试。完整规则及操作见 [发布指南](../guides/RELEASE-GUIDE.md)。

## 验证范围

使用完整升级入口验证正常升级、同名用户文件、受管目录内用户文件、连续升级、失败回滚与缺清单中止。网络、停机、安装和启动验证采用隔离替身，逐场景检查文件内容与归属。测试见 `scripts/test_release_upgrade.py`。
