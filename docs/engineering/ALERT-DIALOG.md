# 统一提示对话框

`frontend/dialogs.js` 提供全局 `showAlert(message)`，由页面在业务脚本之前加载；`dialogs.css` 沿用现有 dialog 配色和按钮样式。正式页面的 19 处提示、附件校验的 3 处提示，以及备份页面的 6 处提示均接入该组件。

组件使用页面内 `<dialog>` 的 `showModal()`，支持确认按钮、Enter、Escape、模态焦点约束及关闭后恢复焦点。多个提示按调用顺序排队；内容使用 `textContent`，保留换行并安全显示错误文本。窄屏宽度受视口限制，长内容可滚动。

`showAlert()` 返回关闭时兑现的 Promise。当前调用均为操作结果提示或校验后退出，保留原有控制流；未来需要等待用户确认再继续的调用应使用 `await showAlert(message)`。

验证入口：`python scripts/test_alert_dialog.py` 使用真实 Chrome 和合成数据，覆盖排队、键盘关闭、焦点恢复、嵌套模态窗口、窄屏长文本、安全文本及附件校验入口。

前端静态资源更新后刷新页面生效。

## 确认框和输入框

需求归档等操作使用 `await showConfirm()`，收口结论输入使用 `await showPrompt()`，备份页面使用相同组件。提示、确认和输入三类对话框共享队列、样式与焦点管理。

确认返回 `true`，取消或 Escape 返回 `false`；输入框确认返回文本（允许空字符串），取消返回 `null`。每次打开均重置返回值，避免前次确认影响后续取消。任务管理操作在等待确认前固定项目参数。

Chrome 回归直接执行真实需求归档函数并使用模拟 API，验证取消时零请求、确认后才发送正确项目的归档请求；补充输入框文本、留空、Escape 取消测试。
