# 引擎维护的工作区资源

## 2026-10-15 创建后流程审查补充

CHAT/WORK 共用系统提示词明确拆解完成的工具契约：全部任务说明、设计依据、验收条件和依赖补齐后，对同一 requirement_id 调用 task_create 并传 complete=true；支持最后一批创建时提交，或 tasks=[] 独立提交。执行者核验返回结果，校验失败时修正后重试。拆解完成仅表示任务规划已提交，任务继续按依赖与项目协作流程推进。

## 使用入口

资源表单中的服务及浏览器配置采用主题背景圆角卡片，内边距 18px、卡片间距 16px；新建向导和已有工作区配置共用该样式。
服务名称、端口、监听地址及移除按钮在宽屏同行排列；600px 以下切换两列。浏览器端口与监听地址并排，数据目录独占一行。

新建和导入向导在成员选择之后增加第六步“工作区资源”，第七步确认。共享主目录只配置一份，独立 worktree 按已选成员配置。返回增减成员时，保留仍存在工作区的输入；更换项目目录会重新生成建议。预览保持数据库和项目文件只读，最终确认保存。

已有项目在“成员 → 工作区”配置资源；独立 worktree 对话框中增加“资源配置”按钮，共享目录直接打开资源表单。共享配置显示共用成员。首次打开旧工作区展示建议值，保存后生效；首次唤醒旧工作区也会自动持久化默认配置。

## 数据及校验

`workspace_resources` 以项目稳定 ID 和规范化实际工作目录为键，保存稳定工作区 ID、资源 JSON 和编辑版本。服务按名称配置端口及监听 IP；浏览器可关闭，开启时配置调试端口、监听 IP、用户数据目录；每个工作区有专用测试数据目录。测试账号引用及数据库名暂缓。

建议值提供 frontend/backend 服务和本机监听的浏览器，端口从 18000–47999 中选择可用值，用户可改为 1024–65535。支持增删服务。默认数据目录位于项目同级 `.bot-group-resources` 下，按项目路径和独立配置标识隔离；目录按使用需要创建，系统配置保存本身只保存路径。

保存时使用工作区锁与 SQLite 写事务校验：工作区内及活跃项目间端口唯一，新增端口检查本机 IPv4/IPv6 占用，Windows 使用独占绑定检测；已保存的端口保持稳定。浏览器和测试数据目录相互独立，禁止配置磁盘根目录、项目目录本身及其祖先。端口探测与未来进程启动存在时间差，启动冲突按系统规则停止启动并协调修改配置。

对已有工作区修改时检查共用该目录的所有成员，运行中拒绝修改；版本冲突返回 409 并要求重新打开。配置更新写审计事件。移除独立 worktree 时释放其配置记录；逻辑移除项目后释放端口分配约束，历史配置保留。已有数据目录保持原状，由项目依据数据保留约定处理。

## 唤醒注入

`wake_system_prompt` 在固定系统规则后注入“当前项目”JSON，新增长期稳定的“工作区配置”：工作区 ID、按服务名排序的端口和监听地址、浏览器配置、测试数据目录。编辑版本、时间、PID、占用状态均保留在系统内部。配置保持不变时，每次唤醒生成的这一段文本完全相同；配置修改后下一次唤醒读取新值。

资源使用约束由引擎系统提示词维护：显式使用配置值，冲突由管理员从工作区配置入口协调，结束时释放本次启动且无需保留的进程。软件模板中的 AGENTS 保留团队交接和测试协作约定，工程文档保留环境及身份权限说明。现有项目文件由用户维护，升级保持原文件内容。
固定系统规则同时要求 Bot 在开发运行入口时，根据脚本、exe 等实际形式，通过参数、环境变量或配置文件接入资源；已有项目首次使用时先检查并适配。启动后核验实际端口、监听地址和数据目录，将验证结果写入交付记录；无法接入时报告具体原因。当前阶段由 JSON 提供资源值，项目依据实际运行接口传值。

## 接口与验证

- `POST /projects/import/preview` 接受并返回 `workspace_resources` 方案，最终导入沿用配置摘要校验及事务回滚。
- `GET/PUT /projects/{name}/workspaces/{profile}/resources`：管理员读取或保存；PUT 需要 config 和 revision。
- `scripts.test_workspace_resources`：只读预览、真实 Git 工作区、共享映射、端口/目录冲突、占用检测、运行及权限门禁、版本冲突、旧项目初始化、稳定 JSON 与失败回滚。
- `scripts/test_project_setup_browser.py` 和 `scripts/test_project_import_browser.py`：七步流程、成员增减、输入保留、共享/独立工作区编辑、390px 深浅主题及原有导入回归。

升级后由用户手动重启引擎并刷新页面；新表通过既有 schema 初始化创建。该功能无需重启 Hermes 网关。

执行结果、资源核验及截图写入项目主目录测试报告；可复用用例和运行条件维护在测试索引。
