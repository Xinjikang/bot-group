# 项目逻辑移除与重新导入

## 操作

- 项目详情、活跃项目和归档项目的下拉列表均提供“移除”，沿用相同确认及逻辑删除流程。
- 确认后退出活跃、归档列表，释放目录绑定。本地代码、文档、Git 及旧配置、成员、权限、负责人、聊天、需求、任务全部保留。
- 已移除项目仅在后台保留记录，界面没有查看、搜索、分页和恢复入口，对应列表及恢复 API 已撤下。
- 再次导入原目录创建新项目 ID，按导入向导配置新团队。旧历史仍属于旧 ID。
- 有待处理/执行中/阻塞任务、等待/运行唤醒、存活 Bot 或受管工作区绑定时拒绝移除，说明需要先处理的占用。

## 数据与接口

projects 的 removed、removed_at 两列启动时幂等迁移。移除同时设置 archived=1，复用已有队列/唤醒/扫描对非活跃项目的拦截；项目与归档列表均过滤 removed=0。

POST /projects/{id}/remove 要求管理员身份。旧 project_remove 调用入口采用逻辑删除；重复移除幂等。工作区互斥锁和 BEGIN IMMEDIATE 保护占用检查与状态更新，project.remove 审计和配置同事务提交。

已移除项目通过归档接口恢复会被拒绝；普通归档项目继续使用原恢复入口，并按 canonical 路径检查活跃项目目录冲突。已移除项目的 worktree 根目录配置释放占用，允许新项目使用；已有受管工作区绑定时仍会阻止移除。

恢复前校验主目录存在；worktree 项目及有登记工作区的项目同时校验主 Git 仓库和全部已登记 worktree 的目录、仓库归属及 Git 登记。校验失败返回 409，保持归档并提示具体路径与恢复原文件/Git 登记后重试。共享普通目录支持无 Git 仓库。恢复操作仅取消归档，文件和仓库由用户从原备份恢复；校验通过与后续启动之间发生的外部文件变更仍由启动校验拦截。

## 验证与部署

- `scripts.test_project_removal`：数据/文件保留、移除后重新导入、列表隐藏、旧列表/恢复 API 撤下、归档入口防绕过、队列禁止唤醒、占用拦截、鉴权、审计失败回滚、并发移除幂等、worktree 目录复用。
- 相关回归：`scripts.test_project_lifecycle`、`scripts.test_project_owner`、`scripts.test_project_workspaces`、`scripts.test_project_permissions`。
- `scripts/test_project_removal_browser.py`：真实 Chrome、隔离 API 验证移除取消/确认、旧项目在活跃/归档列表中隐藏、重新导入及 390px。全部使用临时数据库与项目目录。
- 用户手动重启引擎，再刷新页面。生产项目未执行移除操作。
