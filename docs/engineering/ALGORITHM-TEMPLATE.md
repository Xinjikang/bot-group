# 算法研发模板

模板 ID：`algorithm`，版本以 [manifest](../../templates/projects/algorithm/manifest.json) 为准。适用于传统算法与机器学习研发，接入新建、导入、历史重导入和项目模板参考。

## 角色与流程
| 角色 ID | 名称 | 职责 | 默认管理权限 |
| --- | --- | --- | --- |
| lead | 研发负责人 | 目标、指标、预算、需求任务、成员协调、合并和用户验收 | 10 项需求与任务权限 |
| researcher | 算法研究员 | 文献、基线、方案、理论分析、实验计划和最终报告 | 空 |
| engineer | 算法工程师 | 实现、Demo、数据环境、自测、实验和复现记录 | 空 |
| reviewer | 评审员 | 独立审查理论和实现、评价方法与关键实验复现、返修复审 | 空 |

`owner_role_id=lead`，负责人角色最多一人，执行角色可有多人。管理动作按项目授权执行，任务领取、记录和交接按任务归属校验。角色改名传播到流程及生成文档；角色 SOUL 参考供用户查看、复制和下载。

负责人明确目标、验收标准、预算和停止条件，研究员调研并制定算法方案及实验计划，工程师实现自测并记录实验，评审员按准确提交与方案独立复现。实现问题回工程师、理论和实验设计问题回研究员，范围问题交负责人；修订后复审。研究员汇总报告并交评审员核验，负责人组织用户验收和关闭。

审查、返修、复审及验收结论写入 task node，记录成功后交接具体成员。任务完成与指标达成分别判断；探索任务可以按约定交付负面结论，指标型任务遵循其验收标准。

## 生成文件
模板生成 11 个文件：

| 路径 | 内容 |
| --- | --- |
| AGENTS.md、README.md | 协作、权限、流程及项目入口 |
| docs/INDEX.md | 版本化文档索引 |
| docs/requirements/BRIEF.md | 问题、目标、指标、预算和验收 |
| docs/literature/REVIEW.md | 文献、阅读笔记、方法与基线对比 |
| docs/design/ALGORITHM.md | 算法设计、推导、实验计划和复现条件 |
| docs/engineering/ENGINEERING.md | 实际工程布局、环境、命令与接口 |
| reports/.gitignore、reports/INDEX.md | 本地报告忽略规则与用户阅读入口 |
| reports/REPORT.md | 最终研究报告骨架 |
| reports/experiments/EXPERIMENT.md | 逐次实验记录骨架 |

源码、Demo、配置、数据与模型的实际布局由用户管理。每轮研究按研究编号创建最终报告，每次实验在 `reports/experiments/<实验编号>/` 保存记录和证据。实验记录绑定方案版本、准确代码提交、参数快照、数据与模型版本或校验值、完整命令、环境、硬件、指标与资源消耗。骨架保持待填写状态，实际报告登记到索引。

传统算法检查正确性、复杂度、边界及数值行为；机器学习检查数据划分、预处理拟合范围、数据泄漏和测试协议。评价记录基线公平性、消融、重复试验及波动，区分文献结果、证明、观察与待验证假设。

## 文件、工作区与导入
docs 与源码随任务提交。shared 模式串行写入；worktree 成员从指定基线建立阶段分支，交付准确提交，由负责人协调合并及冲突后的复验。所有实际报告统一写入引擎注入的项目主目录 reports，按独立编号避免覆盖，保留绝对路径及备份。

reports/.gitignore 使用 `*`，报告和原始证据保持本地并随项目备份。worktree 中的初始报告文件作为格式参考，证据通过主目录绝对路径交接。源码包保留模板目录中的报告骨架，项目运行报告遵循发布排除约定。

导入沿用现有补齐机制，保留已有专业文件及用户工程布局；协作规则经预览确认更新。只有旧 doc 目录的项目沿用该目录并调整链接。历史移除项目恢复算法模板类型，显式选择其他模板时按当前选择执行。

## 验证与启用
测试命令见[测试索引](../../scripts/TEST_INDEX.md)。覆盖文件链接、目录边界、权限、返修复审、改名、两种工作区、导入保护、历史恢复、源码打包以及 Chrome 创建和刷新。现有 UI 组件沿用[UI 规范](../ui-spec/UI-SPEC.md)。引擎更新后由用户手动重启，浏览器 Ctrl+F5 后重新打开项目向导。
