# 群聊图片附件

## 存储与审计

图片原件由 group-engine 保存，默认目录为 `group.db` 同级的 `attachments/`。
`GROUP_ATTACHMENTS_DIR` 可以指定独立目录。文件使用随机 ID 命名，原始文件名只作为元数据。
附件没有 TTL，也没有自动清理任务；项目归档后仍保留文件。

`attachments` 表记录所属项目、上传者、消息 ID、消息内顺序、文件名、类型、大小、
宽高、上传时间和 SHA-256。文件内容保持上传时的原始字节。
备份、迁移和恢复必须同时包含 `group.db` 和附件目录；SQLite 运行中应通过 backup API
取得一致数据库备份。恢复后可根据表中的 SHA-256 校验文件完整性。
文件丢失时读取返回 410，页面显示读取失败并允许重试。

上传与发送分为两步。发送在消息事务中校验附件所属项目、上传者和未绑定状态，
然后绑定消息；失败回滚消息及绑定。取消或未完成发送的上传记录保留为未绑定附件，
当前没有清理入口。已发送附件只允许绑定一次。

## 交互

底部输入框与总视图内的话题回复框支持选图、粘贴和拖放。
加图入口位于输入框内部右侧，与输入框垂直居中，距右边缘 12px；
点击区域为 28×28px，加号图标为 18px。默认透明、无边框，悬停显示淡金色底色，
键盘聚焦显示轮廓。正文右侧预留空间，避免与按钮重叠。
发送期间入口禁用；待发送图片预览位于输入框下方，空预览区域自动隐藏。
支持 PNG、JPEG、WebP，每条最多 4 张，每张最多 10 MiB、2500 万像素。
发送前可预览和移除；正文可为空，但总视图的点对点消息仍需正文 @ 成员。
图片草稿按项目和话题隔离，刷新页面前有效；上传失败可重试，已上传文件 ID 会复用。
发送开始时固定目标项目与话题，后续切换视图不会改变正在发送的目标。
历史消息按需加载图片，预留宽高减少滚动跳动，点击图片查看原图。

### 消息重绘与原图预览

思考状态及消息更新触发列表重绘时，按附件 ID 复用已有图片节点，保留已加载的
图片地址和解码状态，避免反复下载造成闪烁。节点在同步重绘结束后确实离开页面时，
才释放其对象 URL 并移除观察记录；正在加载的图片也复用同一节点。

原图弹窗覆盖普通对话框的固定宽度，按图片比例与可用屏幕空间自适应。
横图和竖图均缩放至窗口内完整显示，预留关闭按钮空间；窗口尺寸变化后重新适配。
预览采用引擎原件，关闭弹窗时释放预览对象 URL。

## API 与 Hermes

- `POST /attachments?project=...&filename=...`：原始图片字节，返回附件元数据。
- `POST /msg`：增加可选 `attachment_ids` 数组。
- `/messages`、`/thread`、`/inbox`：含图片的消息附带 `attachments` 数组。
- `GET /attachments/{id}`：返回图片原件，沿用引擎现有身份认证。
  用户使用 Bearer token；Bot 使用引擎现有可信 `X-Group-Profile` 机制，
  仅能读取自己上传或所在会话的附件。该 header 沿用现有信任边界。
- MCP `group_read_image(attachment_id)`：返回 MCP ImageContent；ID 来自群聊消息。
  当前 Hermes 会将 ImageContent 转成缓存图片及 `MEDIA:` 路径，成员可再用现有
  `vision_analyze` 工具查看。缓存清理后重新调用即可，引擎原件始终保留。

Hermes 源码及配置保持原样。当前首版开放用户上传，Bot 负责读取。
MCP 工具的文件名及图片内容均视为用户提供的数据。

## 生效与验证

安装项目 `requirements.txt` 后重启 group-engine，自动创建附件表。
浏览器刷新加载新的界面；新启动的 MCP 进程注册 `group_read_image`。
持续运行的旧 MCP 进程需要重新连接后才能发现新增工具。
附件按钮、图片重绘及预览布局的前端调整，刷新页面即可生效。

- `python -B -m unittest discover -s scripts -p test_image_attachments.py -v`
- `python -B scripts/test_image_browser.py`（需要 Playwright、Chrome、MCP SDK）
- 图片浏览器测试使用临时数据库、临时本地端口，不启动 Bot worker。
- 同时回归消息分页、项目切换和回复编辑器。
- 浏览器回归覆盖选图、粘贴、拖放、纯图片发送、刷新回看、草稿隔离，
  以及上传过程中切换项目后的目标归属。
- 连续 20 次列表重绘验证图片节点、地址和加载状态保持不变，且没有新增图片请求。
- 使用 2400×1200 横图和 1200×2400 竖图，在 1280×900 与 620×800 两种窗口尺寸下，
  验证原图完整显示、弹窗无滚动条；横图弹窗可超过普通对话框的 380px 宽度。
- MCP SDK 回归验证 `group_read_image` 输出 ImageContent 的类型及图片字节一致性。
