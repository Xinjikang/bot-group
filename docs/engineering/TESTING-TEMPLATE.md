# 测试项目模板

模板 ID：`testing`，版本以 [manifest](../../templates/projects/testing/manifest.json) 为准。独立测试项目接入新建、导入、历史重导入与最新角色参考。

## 角色与协作
| 角色 ID | 默认名称 | 专业职责 | 默认管理权限 |
| --- | --- | --- | --- |
| lead | 测试负责人 | 依据、范围、计划、需求任务、资源与阻塞、合并及报告验收 | 10 项需求与任务权限 |
| tester | 测试工程师 | 用例与脚本维护、环境数据、执行、缺陷复现及证据 | 空 |
| reviewer | 测试评审员 | 独立核验覆盖、断言、缺陷和报告，复审修订 | 空 |

`owner_role_id=lead`，负责人角色最多一人，执行角色可有多人；实际管理动作按项目授权执行。角色改名传播到流程和生成文档。SOUL 参考提供专业能力、判断方法、工作步骤、沟通及交付习惯，供用户查看、复制或下载。

负责人确认范围和基线，工程师设计用例与脚本，评审员审查覆盖及断言，工程师按确认版本执行并保存证据，评审员复核结果，负责人汇总报告供用户查阅并按报告交付标准关闭任务和需求。资料、脚本或报告问题在本轮返修复审；产品修复及下一轮测试由用户安排。

产品质量失败、受阻和未执行项如实保留。报告交付验收与产品质量结论分别记录。评审、返修、复审和验收写入 task node，产品缺陷与执行明细写入报告并由节点引用。

## 文件与维护责任
模板生成 15 个文件：

| 路径 | 内容 |
| --- | --- |
| AGENTS.md、README.md、docs/INDEX.md | 协作规则、项目入口和文档索引 |
| docs/product/PRD.md | 权威需求来源、版本、规则、确认状态和待澄清项 |
| docs/product/PROTOTYPE.md | 原型文件或链接、版本、访问方式、页面状态与模拟边界 |
| docs/plan/PLAN.md | 范围、策略、被测版本、资源和判定条件 |
| docs/cases/CASE.md、COVERAGE.md | 用例骨架、需求原型到用例的覆盖及回归范围 |
| docs/environment/ENVIRONMENT.md | 环境、身份、数据、运行、恢复和清理说明 |
| scripts/TEST_INDEX.md | 用例到脚本映射、实际位置、命令、依赖及人工部分 |
| reports/.gitignore、INDEX.md | 报告忽略规则与用户阅读入口 |
| reports/REPORT.md、DEFECT.md、RUN.md | 报告、缺陷和执行记录骨架 |

PRD 与原型由用户提供或指定权威来源，负责人维护版本和确认状态；产品规则冲突交用户确认。初始文件保持待填写状态，原型文件和实际测试脚本按项目技术栈及资料补齐。

用例描述验证目标、步骤和预期，脚本执行步骤与业务断言。一个脚本可对应多个用例，一个用例可跨脚本、环境或参数组合验证。docs/cases/COVERAGE.md 维护需求与原型到用例的关系，scripts/TEST_INDEX.md 集中维护用例与脚本映射，减少重复维护。人工、部分自动化和已自动化分别标注。

工程师根据需求变更更新用例、脚本、数据及索引，在同一交付提交中维护，由评审员核验。用例保持稳定 ID 和修订版本，退役编号保留历史引用。每轮执行固定 PRD、原型、用例、脚本、被测产品及环境版本；产品提交与测试项目提交分别登记。报告区分用例去重、参数化实例和重跑，保留首次失败、尝试次数和最终结果。

## 工作区、报告与导入
新脚本默认放在 scripts，既有脚本沿用原位置并登记到索引。源码、配置、数据和被测产品的实际布局由用户管理。shared 模式串行维护文档与脚本；worktree 以独立阶段分支交付测试资料和自动化，负责人合并并核对冲突后的验证。

所有成员将实际报告写入引擎注入的项目主目录 reports/<测试轮次>/，包含 REPORT.md、DEFECTS.md、RUNS.md 和 evidence。reports/.gitignore 使用 *，写入前核验忽略规则，报告随项目备份；worktree 中的初始文件作为格式参考。历史运行绑定原版本，修订通过新记录引用原编号。

导入保留已有 PRD、原型、用例、脚本索引及报告，补齐缺失骨架，协作规则经预览确认更新。只有旧 doc 目录的项目沿用该目录并调整跨目录链接。历史移除项目恢复 testing 类型，显式选择优先。

## SOUL 参考与验证
本次同时将产品原型参考更新至 1.2.2、算法研发参考更新至 1.0.1，补齐各角色的分析、执行、评审与交付方法。测试三角色侧重风险、用例脚本联动、独立证据核验及报告质量；原型四角色侧重研究、业务规则、交互实现和用户走查；算法四角色侧重理论条件、实验公平性、实现与复现。

项目最新模板参考通过现有接口读取当前资源，历史初始化快照保留原版本；真实 Bot 人格由用户选择采用。测试入口见[测试索引](../../scripts/TEST_INDEX.md)。覆盖三类角色参考的浏览器展示与复制下载、生成、导入保护、权限、报告闭环、历史恢复和源码打包。引擎更新后由用户手动重启，浏览器 Ctrl+F5 后重新打开向导。
