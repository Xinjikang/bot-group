# 产品原型设计模板

模板 ID：`product-prototype`，版本以 [manifest](../../templates/projects/product-prototype/manifest.json) 为准。新建和导入项目向导可选择“产品原型设计”，项目移除后重新导入可恢复历史模板选择。已有项目保留原有文件与团队配置，模板升级通过显式导入和规则确认完成。

## 角色与授权

| 角色 ID | 默认名称 | 专业职责 | 默认管理权限 |
| --- | --- | --- | --- |
| pm | 产品经理 | 目标澄清、PRD、范围与优先级、用户确认、任务统筹、合并验收 | 10 项需求和任务权限 |
| ux | UX 设计师 | 用户研究、信息架构、用户流程、体验设计、UI 规范、实现答疑、走查分析 | 空 |
| prototyper | 原型工程师 | 按 PRD/UX/UI 规范实现 HTML/CSS/JS、模拟数据、自测、覆盖表、预览说明及返修 | 空 |
| reviewer | 原型评审员 | 需求、交互和 UI 一致性验证、问题记录、返修交接与复审 | 空 |

`owner_role_id=pm`，负责人角色由唯一成员承担。执行成员依靠任务归属领取、记录、阻塞和交接，管理动作按项目授权校验。角色 SOUL 参考提供查看、复制和下载，实际宿主配置由用户选择采用。兼容初始化接口要求为全部必需角色分配成员；七步向导沿用现有团队配置规则，实际开始四角色协作前应补齐成员。

## 协作与交付

“优化原型”“修改页面”“开展分析并出报告”等执行请求由产品经理先核对相关需求与任务，再按授权建立或关联需求、拆解任务；已有可承接本轮工作的任务沿用原记录，按当前归属和阶段继续处理。其他成员收到尚无任务承接的请求时，将来源消息和相关记录交给产品经理统筹。范围与验收的待定事项先澄清，任务写明交付物、验收标准、接手人和前置依赖。

话题承担澄清、方案讨论、需求登记与任务规划，具体制作和交付由对应成员在 work 中领取任务并按阶段交接。分析与评审报告沿用同一任务流程，消息形式的报告也保留任务和审查记录。解释概念、询问已有成果和讨论建议可在话题回应；形成执行要求后进入上述受理流程。

产品经理明确目标和范围，UX 开展用户研究、任务分析、信息架构和体验设计；产品经理形成 PRD 与验收标准，UX 形成交互方案并维护 UI 规范。用户确认范围与关键流程后，原型工程师依据 PRD/UX/UI 规范实现并自测，原型评审员按准确文档版本和原型版本独立操作验证。

实现问题交原型工程师，体验方案问题交 UX，需求歧义与范围变化交产品经理。修订后回到评审员复审。优化建议由产品经理决定是否纳入本轮。每轮评审记录需求编号、问题编号、位置、步骤、预期与实际、影响、修订要求、复审条件及未验证项，先保存任务记录再交接。

评审通过后，产品经理组织用户实际走查，UX 分析反馈。确认的调整回到对应环节并完成必要复审。最终由产品经理定稿 PRD、UX 同步体验方案与 UI 规范，核对覆盖表和最终原型后验收。需求变更先确认并更新 PRD，再同步设计、原型和验收标准。研究证据与假设分别标注，用户确认记录来自真实反馈。

协作流程由模板约定和既有任务交接工具执行。每个独立用户目标可形成一个任务，阶段与返修记录保留在同一任务；多任务按前置依赖组织。模板初始化生成待填写骨架，实际研究、设计、原型与验收由项目成员完成。

## 文件与工作区

- `AGENTS.md`、`README.md`：角色分工、流程、权限及协作入口。
- `docs/INDEX.md`：产品设计文档入口。
- `docs/BRIEF.md`：需求简报。
- `docs/design/UX.md`：信息架构、用户流程与体验方案。
- `docs/validation/CHECKLIST.md`、`COVERAGE.md`：检查方法与需求覆盖关系。
- `docs/preview.md`：轻量预览、演示数据和版本交付说明。
- `materials/RESEARCH.md`：用户研究与实际走查发现。
- `materials/references/README.md`：用户资料、竞品截图和证据索引，原始材料保存在同目录或按主题建立子目录。
- `ui-spec/UI-SPEC.md`：默认 UI 规范及项目调整。
- `outputs/PRD.md`：产品需求文档，从起草到定稿持续维护，通过状态和版本标识进度。
- `outputs/prototype/`：原型运行说明，后续添加 HTML/CSS/JS 与合成演示数据。

审查问题、返修要求、复审和最终验收结论统一维护在 task node。覆盖表引用任务 ID 和 node ID；用户走查发现补充到研究资料，确认的产品规则更新进 PRD。资料索引使 references 目录随模板落盘和版本管理，UI 配套素材目录按需创建。

设计依据与交付成果采用 Git 时一起提交和同步。shared 串行写入，worktree 成员在各自工作区维护 docs、materials、ui-spec 和 outputs，由产品经理协调集成及验收。

运行原型使用分配端口与浏览器，明确模拟能力、数据重置方法和未验证项。对外共享按用户确认的目标与可见范围执行。

## 默认 UI 规范

`ui-spec/UI-SPEC.md` 提供可直接采用的浅色 Web 基线：语义色、文字层级、间距和圆角、页面布局、响应规则、按钮/表单/导航/列表/表格/对话框及反馈状态、键盘焦点和动效。附 CSS 变量起始值，原型使用共享样式统一引用。

UX 负责将品牌要求与项目差异落实到该文件并记录版本、确认依据和例外；实现和评审成员同步采用。UI 规范使用独立目录，配套素材按需放入 `ui-spec/assets/`，组件规范可在同目录细分并维护入口链接。需求、体验文档与评审节点引用同一份 UI 规范。

## 既有项目

1.2.0 按 docs、materials、ui-spec、outputs 划分内容，生成 13 个文件。已创建的项目保留原文件，重新导入只补充缺失骨架并按确认更新协作规则。旧路径中的研究、PRD、UI 规范和历史评审内容由维护者按确认的迁移范围整理，核对内容和引用后采用新目录；补齐操作保留旧路径内容，新增骨架仍需项目成员整合。

已有 `doc/` 且没有 `docs/` 的项目沿用 `doc/`，跨目录链接随之调整；ui-spec、materials 和 outputs 保持各自独立目录。目标位置已有 UI 规范保留并列入文档复核。

## 维护与验证

角色参考 1.2.2 补充产品经理的需求取舍和走查验收、UX 的研究分析与状态设计、原型工程师的实现和自测方法、评审员的独立评审与复审标准。参考继续由用户选择采用，历史初始化快照保留原版本。

模板资源、服务端目录列表、向导选项和历史重导入类型同步维护。检查资源路径、预览与落盘一致、角色改名、权限、返修闭环、设计文档版本化、UI 规范引用、导入保护、浏览器创建与刷新。测试命令见 [测试索引](../../scripts/TEST_INDEX.md)。引擎更新后由维护者手动重启，浏览器 Ctrl+F5 后重新打开项目向导。
