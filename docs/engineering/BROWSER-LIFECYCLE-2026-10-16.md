# 浏览器回收与引擎优雅退出

等待超过 120 秒后，由引擎按登记执行终止 Bot 进程树，完成执行收尾和浏览器回收后退出；清理失败恢复派发。完整重启行为见 [服务重启说明](SERVICE-RESTART-2026-10-17.md)。

## 关闭时机

browser-harness 按以下事件回收：

| 事件 | 回收范围 |
| --- | --- |
| 任务交接成功 | 该任务交出方的实例 |
| 任务完成、取消（含需求撤回带来的任务取消） | 该任务的实例 |
| 项目归档、移除 | 该项目的实例 |
| 引擎退出 | 引擎登记的全部实例 |

任务状态成功提交后执行清理。返回值 `browser_cleanup` 报告结果；失败保留登记和日志，任务流转结果保持已提交状态。仍在收尾的执行可能再次使用工具，因此收到释放请求的实例在执行退出时补做一次清理。普通执行结束、思考间隙、等待和任务阻塞保持资源；后续由上述事件回收。

## 归属与释放

每次引擎唤醒给子进程分配独立 `BH_RUNTIME_DIR`、`BH_TMP_DIR` 和默认 `BU_NAME`。两个目录启用按名称区分文件，兼容工具显式指定多个会话名。`browser_resources` 记录项目、成员、执行会话/时间、话题和任务；执行中领取新任务时更新关联。聊天与工作、不同项目及不同执行相互隔离。

清理只读取引擎登记目录下的 PID/端点文件，通过本地认证 IPC 的 `ping` 核对 PID，再发送 `shutdown`。等待进程退出和端点消失，移除已经核验退出的 PID 文件。使用 harness 自身的关闭能力回收专属标签页和连接；共享 Chrome 继续由其所属服务管理。截图和日志保留。全局默认实例、用户浏览器和其他宿主创建的实例保持原有管理方式。

该回收机制管理 browser-harness。其他浏览器后端沿用各宿主生命周期；全局默认实例由其所属服务管理。

## 优雅退出

`python -m engine.main` 使用受管 Uvicorn Server。管理员 `POST /admin/shutdown` 和正常退出信号进入同一流程：

1. 与启动执行共用锁，关闭新执行入口，队列/扫描线程保持存活并暂停轮询。
2. 保持 HTTP/MCP 服务可用，最多等待 120 秒供当前 Bot 执行收尾。排队任务保留，供下一次启动继续。
3. 超时则进入 terminating，终止登记的 Bot 进程树并确认执行收尾；随后释放登记的浏览器资源。清理成功后请求 Uvicorn 正常关闭连接、执行 lifespan 收尾并退出。

SSE 在最终停止事件设置后结束。`GET /admin/shutdown` 返回 draining/terminating/releasing/stopping/failed 状态。清理失败且最终退出尚未开始时恢复入口，管理员处理占用后可重试。系统强制终止或断电可能跳过进程内清理。

`stop.sh` 经服务入口加载本地凭据并调用 `tools/stop_engine.py`，发出管理员退出请求并验证原引擎进程和端口退出，默认最多等待 180 秒。`start.sh` 复用同一停止流程，退出失败就停止启动。

首次从缺少退出接口的旧版升级时，由用户手动停止旧服务。引擎代码需重启加载；Hermes 网关内已有 MCP 进程需用户重启网关。

## 验证

- `scripts.test_browser_resources`：隔离 SQLite、任务事件/领取绑定、跨项目/聊天隔离、失败可重试、真实 TCP 守护进程退出与 PID 不匹配保护。
- `scripts.test_engine_shutdown`：退出门禁、等待当前执行、超时/失败保留服务、临时引擎管理员权限、SSE、浏览器后台进程及监听端口退出。
- `scripts.test_browser_harness_integration`：设置 `BROWSER_HARNESS_PYTHON` 指向现有 harness Python，用 Playwright 启动临时 Chromium；确认专属标签页消失、原有标签页保留、两个 Python 进程退出、临时工作目录可删除。

全部验证使用临时库、临时进程和临时浏览器；线上引擎和生产任务保持运行状态。

执行结果与资源回收证据保存到项目主目录测试报告。
