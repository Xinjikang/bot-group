# Windows 临时目录环境变量污染

## 故障机制

在 Git Bash 中，已导出的局部变量 `tmp` 被复用于原子写入的临时文件名时，新值仍向子进程导出。Windows 环境变量名不区分大小写，原生进程可能把该值作为 `TMP` 使用；MSYS 路径再经原生解析，可能产生重复盘符片段和异常临时目录。

持续 shell 保存和恢复导出环境时，污染会延续到后续命令。项目工作目录与临时目录变量应分别核查。

## 排查与处理

1. 对照 shell 的 `tmp/temp` 与原生进程的 `TMP/TEMP`，核验值及路径解析结果。
2. 追踪变量首次赋值、环境快照与启动子进程的边界。
3. 在隔离实验中比较取消小写变量导出后的结果。
4. 经授权修改 shell 初始化或上游实现后，刷新旧快照，验证写文件、后续命令和跨项目操作。

源码使用专有临时变量名并限制作用域。外部宿主源码与生产配置按其授权边界处理。

2026-10-17 的隔离实验验证了污染机制和取消导出的阻断效果，现场记录保存在主目录测试报告 `hermes-temp-path/2026-10-17/REPORT.md`。目录生成进程的精确归因及生产修复效果需要独立证据。
