# HTTP 访问控制与成员凭据

## 认证与路由边界

`engine/access.py` 为业务路由提供统一入口。公开入口为 `GET /auth/status` 与 `POST /auth/login`。静态 `/app/`、接口模式文档和 `/health` 的基本存活字段可公开访问。`/health` 的程序根和数据库路径只向管理员身份返回。

| 身份 | 认证方式 | 访问范围 |
| --- | --- | --- |
| 管理员 | `Authorization: Bearer <token>` | 管理、配置、目录、全局读取、审批、话题管理和 SSE |
| 本机免密管理 | 管理密码为空且直连客户端为回环地址 | 管理员范围；Origin 必须匹配本站，跨站浏览器请求被拒绝 |
| 成员 | `X-Group-Profile` 和 `X-Group-Key` | 明确列入 `BOT_ROUTES` 的接口，并受项目、话题和自身资源检查 |

成员凭据存在时优先按成员身份处理。无效凭据返回 401；已认证身份越权返回 403。新增业务路由默认仅向管理员开放；成员接口需加入访问契约并实现资源范围检查。

成员可以查询自己有效参与的项目花名册、话题和收件箱，发送所属项目/话题消息，处理自己的已读与心跳。话题列表只包含自身参与且项目成员资格有效的话题。`/task-tools/{operation}` 继续校验项目成员资格、操作白名单、业务权限与执行上下文；附件读取沿用消息和项目授权。全局消息、队列、任务、推理、发现扫描、配置、成员注册、审批与话题管理均为管理员入口。

免密模式用于本机直连；密码为空时管理员 Bearer token 校验关闭，避免空密码派生签名被用于远程认证。通过回环反向代理提供远程访问时，应配置管理员密码，确保代理转发的请求也需要认证。远程部署同时使用 HTTPS。

## 成员凭据生命周期

引擎以 HMAC-SHA256 为具体 profile 派生成员凭据。服务启动初始化受操作系统权限保护的持久签名文件，保存当前代和必要的退役代；首次初始化可导入 `GROUP_ENGINE_KEY`。通用成员凭据只接受当前代。代次轮换、跨重启网关执行及恢复检查见 [签名密钥与逐执行撤销](HERMES-GATEWAY.md#签名密钥与逐执行撤销)。主密钥只保留在引擎侧。

引擎启动 Codex/Hermes 时，通过 MCP 环境注入 `GROUP_ENGINE_TOKEN`，子进程兼容入口为 `XDG_GROUP_ENGINE_TOKEN`。自动执行使用单次执行签名凭据，绑定 profile、项目、话题、session 和启动时间；MCP 用此值填写 `X-Group-Key`。任务请求省略 `execution` 时由凭据恢复上下文，显式上下文必须与凭据一致。CHAT 执行仍可拆解和修订任务，领取、流转、完成及阻塞操作要求 WORK 执行。执行结束或被新执行替代后，其任务调用失效。消息发送也校验凭据绑定的执行与消息上下文一致。

管理员密码、管理员签名密钥和成员派生主密钥从 Bot 子进程继承环境中移除。凭据属于持有者凭证，宿主配置、进程环境和运行目录仍需使用操作系统权限保护。

Codex 与旧版 Hermes CLI 使用当前代执行凭据，按 `(session, started_at)` 匹配 `wake_runs`，要求运行时为 `codex` 或 `hermes`、执行尚未结束且成员/项目/话题一致。缺失记录、结束执行、身份不匹配或旧代凭据返回 401。Hermes 网关执行优先校验其持久执行账本，保留跨引擎重启及终态撤销契约。

手动接入 stdio MCP 时，管理员通过 `POST /auth/member-token`，请求体 `{"profile":"bot-12"}`，取得已注册成员凭据，并将返回的 `token` 配置到该 MCP 进程的 `GROUP_ENGINE_TOKEN`。响应使用 `Cache-Control: no-store`。签名代次轮换后需重新获取手工凭据并重载宿主；引擎管理的执行自动注入新凭据。

手工成员凭据按成员与项目授权访问，允许省略执行上下文；显式提供上下文时仍校验对应执行。该凭据应交由可信的手工宿主管理，引擎自动执行仅获得绑定执行的凭据。

任务写接口在实际写事务取得 `BEGIN IMMEDIATE` 后复查当前成员资格、项目状态和执行有效性，复查与业务写入共用连接和事务。话题任务修订同时复查话题成员和开放状态。拆解中的凭据必须同时匹配持有成员；有执行上下文的请求使用引擎派生的拆解标识。需求查询和任务上下文响应隐藏拆解凭据及失效凭据列表；创建响应保留当前持有成员续写所需的 `credential`。拆解接管、幂等重试和完成后的授权修订继续遵循任务状态机。

手工调用 `task_create` 时，省略 `credential`、传入 `null` 或空字符串均表示由引擎取得拆解权并返回非空凭据；后续修订草稿、分批创建及完成提交应携带返回值。`task_update` 校验非空凭据和持有成员，缺少有效凭据返回 `decompose_credential_stale`。已有空凭据锁的持有成员可再次调用 `task_create` 取得有效凭据；其他成员仍受占用和超时接管规则约束。

附件读取先验证当前项目成员资格，再检查附件所属会话。成员停用、项目归档或移除后，历史收件箱与话题成员记录均无法继续授权附件读取。管理员保留历史附件访问权限。本地免密码管理员可上传图片并创建图片开场话题，附件和开场消息统一归属 `user`。

升级与回滚的停机闸门读取安装数据目录 `.env`，进程环境保持优先；启用管理员密码时，健康检查及停机请求均附管理员凭据。停机前继续核对程序根、数据库路径及实例标识，退出后确认进程和端口均已释放。

## 登录与浏览器事件流

密码按 UTF-8 字节做恒定时间比较。密码错误或非字符串返回 401。登录按直连客户端地址统计所有尝试，60 秒最多 10 次，超限返回 429 和 `Retry-After: 60`；计数器具有互斥锁和容量上限。代理后的客户端共用代理地址对应的限额。

普通 API 使用 Bearer token。原生 EventSource 使用 `group_events` HttpOnly、SameSite=Strict cookie，路径限定 `/events`，HTTPS 下启用 Secure。页面持已有 token 刷新时，通过 `POST /auth/events` 恢复事件 cookie，再建立 SSE；退出时关闭事件流并调用 `POST /auth/logout` 清除 cookie。cookie 仅用于 SSE 读取，其他接口仍要求显式管理员认证。管理员 token 维持既有有效期与签名校验语义。

## 需求终态与任务推进

创建、领取、扫描、重试选择和失败重试均要求父需求处于 `open` 或 `blocked` 且 `archived=0`。交接、完成、阻塞、修订、恢复和审批放行在写事务内执行同一生命周期检查。`done`、`cancelled`、已归档或缺失的父需求返回 `requirement_inactive`，扫描和重试跳过相应任务。

拆解提交要求至少存在一个任务；所有未取消任务须已发布且说明完整，依赖须存在。失败返回 `decompose_incomplete`，本次创建与完成提交一并回滚；先前批次草稿保留，可补全发布后重新提交。
