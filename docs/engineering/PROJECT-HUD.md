# 项目维护 HUD

HUD 位于顶栏中间。维护 Bot 可与负责人相同，也可独立选择。HUD 使用独立的逻辑会话、历史表和模型调用通道；群消息、任务队列及宿主原会话保持各自归属。

## 启用与提问

在 HUD 设置中选择已有 Bot 或创建 profile，点击“保存并开始维护”。默认 AI 只影响后续预选；各项目通过“开始维护”单独启用。首次启用会检查项目，之后配置、未完成需求、任务状态及文档变化触发检查。后台合并同一状态的重复检查，失败等待显式重试，待答问题持续保存。

问题包含原因和最多五个选项，推荐答案位于首项。用户可以选择一个选项并补充文字，也可以完全自行输入。选项与输入在刷新后恢复，Ctrl+Enter 发送，Escape 收起并返回 HUD 按钮焦点。其他项目的待答问题显示在 HUD 内的项目入口。

开放式问题可以只提供题目和原因，服务端把省略的选项归一为空列表，页面兼容已有的无选项记录。配置提案占据当前交互，确认后基于更新的资料生成下一问。

## 创建与维护

创建/导入向导按阶段保存名称、目录、模板、协作方式、团队、规则正文和资源草稿。恢复时重新核对目录、Git 与规则确认状态。维护提案确认后同步表单；直接编辑表单使旧提案失效。创建完成以 `project_setup_requests` 成功回执把维护会话绑定正式项目；绑定可重试。

维护 AI 读取模板职责、流程、文档骨架和实际项目配置。已有项目实际目录与规则优先。空项目从目标、输入和产出开始。文件内容包含 SHA-256 和截断标记，最多列出 160 个普通 Markdown/文本文件，单轮正文总量上限 45,000 字。链接、隐藏目录、依赖、报告、目标源码副本及常见凭据文件被排除。此版本对大量资料采用有界上下文，尚未提供全文检索、远程资料下载和文件上传。

提案可以修改向导基础字段，已建项目可更新名称与简介；其他目录用途、资料位置、版本与约定经确认后保存为维护事实。事实的权威存储为项目 `settings.maintenance_facts`，后续 Bot 唤醒把它作为项目资料注入。HUD 保留确认记录。目录迁移、文件重组、Git remote 设置和工作区资源变更继续使用相应的专用流程。

模型上下文显式区分创建草稿与正式项目。提示约束要求目录用途提案描述实际登记能力、端口建议标注待检查、用户回答标注来源，并将模板默认约定作为待采纳建议。模型文字仍需结合实际执行结果判断；字段校验、提案确认及修订冲突由引擎强制执行。

## 存储与并发

`hud_sessions`：稳定 ID、项目归属、Bot、阶段、修订号、模型上下文代次、状态、草稿、待答问题、配置提案和确认事实。每个正式项目只有一个维护会话；草稿使用独立 ID。

`hud_entries`：追加维护发言及配置确认记录，带会话和代次。空闲重置默认 30 分钟，可设 5 分钟至 24 小时。下一轮在过期后换代，持久事实、用户决策与待答问题保留。模型每轮在独立临时宿主中根据该代历史与项目快照重建上下文。

一次超时续接只增加一个上下文代次，模型完成时刷新活动时间，避免同一轮保存结果时重复换代。

所有维护 HTTP 接口要求管理员身份。写入携带 `revision`，并发变更返回 409；模型结果按启动时的修订号比较，过期结果丢弃。切换阶段把未答问题转为待核对资料。服务重启把运行中的检查标记为失败，避免自动重复请求。后台只处理已启用会话。

## 模型与运行

`hud_runtime.py` 读取选定 Bot 的模型路由；Hermes 使用独立进程中的无工具 AIAgent，Codex 使用隔离 CODEX_HOME、只读沙箱和关闭 shell 工具的 exec。配置、认证副本仅存在于临时目录，完成后清理。单次模型调用最长 180 秒，超时终止其进程树。真实宿主与模型的兼容性需通过现场联调确认。

Hermes 工作进程移除脚本目录对模块搜索路径的影响，避免本地 `queue.py` 遮蔽标准库；宿主 `.env` 中的 HERMES、CODEX、GROUP、XDG 路径设置保持隔离进程的值。错误诊断只输出阶段、异常类型及栈帧位置，省略异常正文。经明确授权可运行 `scripts/verify_project_hud_live.py`，按精确服务路由执行五轮合成场景，记录原宿主配置摘要、群会话隔离与临时目录清理结果。

`scripts/preview_project_hud.py` 提供独立 SQLite 和固定响应的本地交互验证服务，明确标记“本地验证”，不连接模型。其测试重置接口只存在于该脚本的预览实例。生产入口为 `python -m engine.main`。

API：`POST /hud` 创建/取得会话；`GET /hud` 待办与草稿；`GET/PATCH /hud/{id}` 读取/配置；`POST /answer` 回答；`POST /accept` 确认提案；`POST /retry` 启用或重试；`POST /bind` 绑定成功创建回执。
