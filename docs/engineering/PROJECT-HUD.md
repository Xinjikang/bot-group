# 项目维护 HUD

旧版 Hermes CLI 的临时数据目录调用设置 `HERMES_DISABLE_LAZY_INSTALLS=1`，保持当前 CLI 解释器和依赖环境，防止临时 home 触发运行时切换。子进程错误输出仅保留末尾 16 KiB 用于分类；依赖导入错误提示修复运行环境，其他失败显示退出码，原始错误输出与凭据保持不向页面透传。

HUD 位于顶栏中间。维护 Bot 可与负责人相同，也可独立选择。HUD 使用独立的逻辑会话、历史表和模型调用通道；群消息、任务队列及宿主原会话保持各自归属。

## 启用与提问

在 HUD 设置中选择已有 Bot 或创建 profile，点击“保存并开始维护”。默认 AI 只影响后续预选；各项目通过“开始维护”单独启用。首次启用会检查项目，之后配置、未完成需求、任务状态及文档变化触发检查。后台合并同一状态的重复检查，失败等待显式重试，待答问题持续保存。

问题包含原因和最多五个选项，推荐答案位于首项。选项属于当前待答问题，点击后直接发送；输入框已有补充时一起发送，也可完全自行输入并发送。成功后选项消失，回答保留为用户消息，刷新后恢复对话和未发送输入。AI 正文、用户消息及确认记录按时间顺序显示，当前问题或提案附在 AI 回复下。原因默认折叠，项目备注和设置放入次要入口。Ctrl+Enter 发送，Escape 收起并返回 HUD 按钮焦点。

检查期间，正文上方固定一行最新推理摘要和经过秒数。摘要来自宿主可展示的 reasoning 回调或 Codex reasoning 事件，保留最近 500 字符并将显示位置移到末尾；新内容替换旧内容。宿主尚未提供摘要时显示实际处理阶段，收起状态的标题同步最新文字。结束或失败后停止计时并隐藏进度行。刷新恢复当前进度，摘要更新按会话修订号隔离，保持配置修订号与输入内容稳定。

开放式问题可以只提供题目和原因，服务端把省略的选项归一为空列表，页面兼容已有的无选项记录。配置提案占据当前交互，确认后基于更新的资料生成下一问。

场景由结构化结果驱动：`question` 展示选择或自由回答，`proposal` 展示确认，`guide` 展示使用说明，其他回复展示对话。`guide` 包含标题与 1 至 8 个 `title/body` 步骤，服务端校验长度和字段后随回复保存。提案及问题优先于说明，单轮仅呈现一个主要场景。新回复切换当前场景；用户可随时查看完整对话并返回当前问题或说明。历史说明仍可展开阅读。所有模型文本以文本节点呈现。

模型返回普通文本时，运行时将其归一为仅含 `text` 的对话回复，继续经过正文长度校验和历史保存。以 `{`、`[` 或代码围栏开头的结果按结构化输出处理，解析失败时保留重试错误；空输出同样报错。合法 JSON 仍须通过字段、提案权限和修订校验，配置变更继续等待用户确认。

## 创建与维护

项目详情打开期间，HUD 跟随详情中的项目。详情关闭后恢复顶栏项目上下文；切换上下文保留各会话输入。弹窗外部点击处理把 HUD 视为协作界面，展开、回答及收起 HUD 时保留详情标签与未保存字段。

HUD 展开时读取详情边界，将自身放在详情右侧并与其同高；详情坐标和尺寸保持原值。ResizeObserver 跟踪详情内容引起的高度变化，窗口缩放重新计算右侧可用宽度。收起时移除贴靠样式，恢复顶栏位置。右侧可用宽度不足 300px 时沿用原有浮层，详情保持原位。

创建/导入向导复用上述定位逻辑，以所在向导作为贴靠参照，保留向导原有位置与尺寸。右侧间距为 8px，展开后顶部对齐且等高，两侧正文独立滚动；右侧可用宽度不足 300px 时使用原有浮层。助手保留在向导节点内，收起、Escape 和切换阶段保留表单草稿；关闭向导后恢复全局位置并立即重新计算贴靠状态。

创建/导入向导按阶段保存名称、目录、模板、协作方式、团队、规则正文和资源草稿。恢复时重新核对目录、Git 与规则确认状态。维护提案确认后同步表单；直接编辑表单使旧提案失效。创建完成以 `project_setup_requests` 成功回执把维护会话绑定正式项目；绑定可重试。

维护 AI 读取模板职责、流程、文档骨架和实际项目配置。已有项目实际目录与规则优先。空项目从目标、输入和产出开始。README、AGENTS、文档索引和工程入口优先，其次读取入口直接链接的文档。最多读取 160 个普通 Markdown/文本文件，单轮正文总量上限 60,000 字，保留 SHA-256、截断和未读取标记；文件扫描上限 2,000 项、五层目录，结构概览上限 180 项。符号链接、隐藏目录、依赖、报告、目标源码副本及常见凭据文件被排除。目录概览表示有限范围，路径缺失须结合实际检测判断。全文检索、远程资料下载和文件上传属于后续能力。

`hud_inspection.py` 使用固定只读检查：项目目录、Git 仓库范围、远程 URL 配置是否存在、工作区修改、CodeGraph 安装入口与索引状态、本地文档链接、成员职责、独立工作区根目录与资源登记。Git 远程只传递远程名称，URL 和认证信息留在本机。探针单次超时 6 秒、返回上限 256 KiB，失败标为 unknown；CodeGraph 使用公开 `status --json`，未知版本或输出格式保留待核实状态。网络连通性、实际端口可用性及正式发布状态另行核验。检测结果参与自动变化摘要，每次对话重新读取；模型结合文档约定判断可选能力、使用阶段与语义矛盾。

助手正文使用现状、影响和下一步解释项目，已读取文档直接作为依据。用户的新约定经确认保存为“项目备注”，界面说明本项目助手和成员 Bot 会参考。配置卡片分别显示项目设置/向导草稿与项目备注的保存位置、当前内容和建议内容。当前内容由引擎生成，无变化项自动移除；确认前保持原值，暂不处理或自由回复可撤下旧建议。

提案可以修改向导基础字段，已建项目可更新名称与简介；其他目录用途、资料位置、版本与约定经确认后保存为维护事实。事实的权威存储为项目 `settings.maintenance_facts`，后续 Bot 唤醒把它作为项目资料注入。HUD 保留确认记录。目录迁移、文件重组、Git remote 设置和工作区资源变更继续使用相应的专用流程。

模型上下文显式区分创建草稿与正式项目。提示约束要求目录用途提案描述实际登记能力、端口建议标注待检查、用户回答标注来源，并将模板默认约定作为待采纳建议。模型文字仍需结合实际执行结果判断；字段校验、提案确认及修订冲突由引擎强制执行。

## 存储与并发

`hud_sessions`：稳定 ID、项目归属、Bot、阶段、修订号、模型上下文代次、状态、草稿、待答问题、配置提案和确认事实。每个正式项目只有一个维护会话；草稿使用独立 ID。

`hud_entries`：追加维护发言及配置确认记录，带会话和代次。空闲重置默认 30 分钟，可设 5 分钟至 24 小时。下一轮在过期后换代，持久事实、用户决策与待答问题保留。模型每轮在独立维护会话中根据该代历史与项目快照重建上下文。

一次超时续接只增加一个上下文代次，模型完成时刷新活动时间，避免同一轮保存结果时重复换代。

所有维护 HTTP 接口要求管理员身份。写入携带 `revision`，并发变更返回 409；模型结果按启动时的修订号比较，过期结果丢弃。切换阶段把未答问题转为待核对资料。服务重启把运行中的检查标记为失败，避免自动重复请求。后台只处理已启用会话。

## 模型与运行

专用指令与项目资料分开传递：Hermes 网关创建会话时通过 `client_env.HERMES_EPHEMERAL_SYSTEM_PROMPT` 注入，旧版 CLI 使用隔离进程的同名环境变量；Codex 临时配置使用 `developer_instructions`（[官方配置契约](https://learn.chatgpt.com/docs/config-file/config-reference)）。模型的用户输入仅包含项目资料、检测结果和对话。网关重试摘要同时覆盖专用指令和用户输入，保留原执行回执核对规则。

`hud_runtime.py` 复用群聊的 `hermes_gateway.enabled()` 判定：具备新版网关布局的 Hermes（0.22.x 路线）通过现有 `hermes_gateway.connection()` 连接公开 `/api/ws`；旧版通过公开 `hermes chat -Q --ignore-rules --query-file -` 子进程调用。判定依据与群聊一致，由已安装入口对应的源码布局识别，连接错误继续报告网关错误。项目助手调用链仅使用公开 CLI 和 RPC。

`hud_gateway.py` 复用群聊的会话创建、恢复与传输接口，使用唯一标题的 ACP 维护会话。会话沿用所选 profile 的模型配置，通过公开 `toolsets: [no_mcp]` 排除全局 MCP，空 editor MCP 清单、`ignore_rules`、关闭 checkpoints/hooks 保持原有维护权限边界。提交前查询 `tools.show`，工具数为零才继续。工具白名单、文档写入与提案确认属于独立能力边界。

会话级 `config.set show_reasoning=1` 开启公开推理事件，按 session_id 过滤 `reasoning.delta`，通过现有 HUD 进度回调显示最新一行。模型与宿主决定事件是否提供；等待期间保留阶段与耗时显示。

`hud_sessions.state.gateway` 保存 request/submission/admission ID、原 profile home、提示摘要和截止时间。断线或引擎重启后，显式重试先核对原 admission 回执；提交确认丢失时保留会话标识并报告待核对，防止重复发起未知执行。检查预算为 180 秒，届满对排队输入执行 `prompt.cancel`，运行输入按原 generation 执行 `session.interrupt`，再核对终态，最多等待 30 秒。未确认终态继续保留原执行记录。

旧版 Hermes 与 Codex 使用临时配置和认证副本，完成后清理。Hermes 临时配置关闭 CLI 工具、MCP、记忆和 checkpoints；Codex 使用隔离 CODEX_HOME、只读沙箱和关闭 shell 工具的 exec。子进程按 UTF-8 消费输出，独立线程发送输入、读取输出和排空错误，超时终止进程树。清除继承的 Python 环境标记；Codex JSON 事件继续支持已有进度显示。

`scripts/verify_hud_gateway.py --inspect-only` 使用独立会话核验公开创建、工具清单与推理显示配置，全程省略模型提交。`--live` 在明确模型、服务商、域名及合成资料发送范围后验证单次提交与完成回执。验证记录包含会话标识，宿主配置保持原值；测试命令及参数见 `scripts/TEST_INDEX.md`。

`scripts/preview_project_hud.py` 提供独立 SQLite 和固定响应的本地交互验证服务，明确标记“本地验证”，不连接模型。其测试重置接口只存在于该脚本的预览实例。生产入口为 `python -m engine.main`。

API：`POST /hud` 创建/取得会话；`GET /hud` 待办与草稿；`GET/PATCH /hud/{id}` 读取/配置；`POST /answer` 回答；`POST /accept` 确认提案；`POST /retry` 启用或重试；`POST /bind` 绑定成功创建回执。
