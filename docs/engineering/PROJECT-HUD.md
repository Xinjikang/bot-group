# 项目维护 HUD

旧版 Hermes CLI 的临时数据目录调用设置 `HERMES_DISABLE_LAZY_INSTALLS=1`，保持当前 CLI 解释器和依赖环境，防止临时 home 触发运行时切换。子进程错误输出仅保留末尾 16 KiB 用于分类；依赖导入错误提示修复运行环境，其他失败显示退出码，原始错误输出与凭据保持不向页面透传。

HUD 位于顶栏中间。维护 Bot 可与负责人相同，也可独立选择。HUD 使用独立的逻辑会话、历史表和模型调用通道；群消息、任务队列及宿主原会话保持各自归属。

## 启用与提问

模型结果可携带 `notification: {kind, action?}`：`none` 用户当前无待办，`pending` 已有等待用户回答或确认的卡片，`user_action` 需要用户当前介入。`user_action` 必须提供非空 `action`，描述具体行动与当前原因。脚本修改、提交、索引更新等执行成员职责使用 `none`，进度和检查结果保留在对话。服务端将普通提醒按实际保留的问题、提案和卡片归一为 `pending` 或 `none`。前端对历史数据同样以实际卡片决定普通待办标记，单独的旧 `pending` 保持安静。服务端在会话 state 保存带 ID 的提醒，并在会话列表返回提醒与提案。

前端仅依据明确的 `user_action` 自动展开，并生成行动说明卡片；其余待办在收起 HUD 显示“有待处理事项”，用户已展开的面板保持原状。行动 ID 优先使用未完成提案/问题 ID，手动收起通过 sessionStorage 抑制同一提醒，刷新当前标签页后继续生效。消息区固定包含“对话消息”和“待办事项”两个标签，默认对话页，待办页显示当前会话卡片及数量。提醒只控制展开，保持正在阅读的标签。轮询仅获取当前会话，菜单仅保留项目备注和设置；其他项目及其他创建草稿保持各自上下文。排队处理新输入时清除上一轮提醒，新的结果重新分类。

在 HUD 设置中选择已有 Bot 或创建 profile，点击“保存并开始维护”。默认 AI 只影响后续预选；各项目通过“开始维护”单独启用。首次启用、创建完成、用户输入与显式重试立即执行；后台准备检查默认间隔一小时，间隔内跳过资料扫描。相同配置与资料摘要合并重复检查，失败等待显式重试，待答问题持续保存。

问题包含原因和最多五个选项，推荐答案位于首项。选项点击时携带该卡片输入框的补充，也可在卡片内自行输入并发送。成功后对应问题卡消失，回答保留为用户消息；切换标签保留卡片与对话输入，刷新后恢复本轮对话和已保存的对话输入。对话页最多显示两条：最近一条用户消息（存在时显示，正文 12px）和该消息之后的最新助手回复；尚无用户消息时只显示最新助手回复。发送成功后更新本轮消息，等待期间仅显示新用户消息。系统确认记录和历史往来继续保存在后台。问题、提案与行动提醒以卡片展示在待办页，使用说明随回复展示在对话页。原因默认折叠，项目备注和设置放入次要入口。Ctrl+Enter 发送，Escape 收起并返回 HUD 按钮焦点。

检查期间，正文上方固定一行最新推理摘要和经过秒数。摘要来自宿主可展示的 reasoning 回调或 Codex reasoning 事件，保留最近 500 字符并将显示位置移到末尾；新内容替换旧内容。宿主尚未提供摘要时显示实际处理阶段，收起状态的标题同步最新文字。结束或失败后停止计时并隐藏进度行。刷新恢复当前进度，摘要更新按会话修订号隔离，保持配置修订号与输入内容稳定。

开放式问题可以只提供题目和原因，服务端把省略的选项归一为空列表，页面兼容已有的无选项记录。配置提案占据当前交互，确认后基于更新的资料生成下一问。

内容由结构化结果驱动：`question` 与 `proposal` 统一渲染为待办卡片，`guide` 随对话消息展示使用说明。`guide` 包含标题与 1 至 8 个 `title/body` 步骤，服务端校验长度和字段后随回复保存。顶层单问题和单提案与 `cards` 数组统一呈现在待办页，按 ID 避免顶层记录重复，数量不限，内容较长时滚动。问题通过自身选项或输入框单独回答，提案通过自身 ID 确认或暂不处理。`user_action` 的行动说明显示为独立提醒卡片。卡片数量与消息正文的两条限制相互独立。两个标签支持方向键与 Home/End，切换项目默认回到对话页，空待办页显示明确空状态。

未完成卡片持久保存在 `state.cards`，模型上下文通过 `pending_cards` 提供完整集合；新轮次追加独立卡片，按问题/提案内容合并完全重复的事项。处理一张只移除对应 ID，剩余卡片继续保留；提案逐一校验可修改字段及其当前值，独立字段的确认可连续完成。历史单问题/提案继续兼容。会话列表返回完整待办集合，当前项目 HUD 使用会话详情渲染卡片。后台保留完整历史，所有模型文本以文本节点呈现。

模型返回普通文本时，运行时将其归一为仅含 `text` 的对话回复，继续经过正文长度校验和历史保存。以 `{`、`[` 或代码围栏开头的结果按结构化输出处理，解析失败时保留重试错误；空输出同样报错。合法 JSON 继续通过字段、提案权限和修订校验。明确要求执行的配置修改通过原生工具保存，主动提出的配置建议使用提案卡片确认。

## 创建与维护

项目详情打开期间，HUD 跟随详情中的项目。详情关闭后恢复顶栏项目上下文；切换上下文保留各会话输入。弹窗外部点击处理把 HUD 视为协作界面，展开、回答及收起 HUD 时保留详情标签与未保存字段。

HUD 展开时读取详情边界，将自身放在详情右侧并与其同高；详情坐标和尺寸保持原值。ResizeObserver 跟踪详情内容引起的高度变化，窗口缩放重新计算右侧可用宽度。收起时移除贴靠样式，恢复顶栏位置。右侧可用宽度不足 300px 时沿用原有浮层，详情保持原位。

创建/导入向导复用上述定位逻辑，以所在向导作为贴靠参照，保留向导原有位置与尺寸。右侧间距为 8px，展开后顶部对齐且等高，两侧正文独立滚动；右侧可用宽度不足 300px 时使用原有浮层。助手保留在向导节点内，收起、Escape 和切换阶段保留表单草稿；关闭向导后恢复全局位置并立即重新计算贴靠状态。

创建/导入向导按阶段保存名称、目录、模板、协作方式、团队、规则正文和资源草稿。恢复时重新核对目录、Git 与规则确认状态。维护提案确认后同步表单；直接编辑表单使旧提案失效。创建完成以 `project_setup_requests` 成功回执把维护会话绑定正式项目；已有所选 AI 时自动排队检查，尚未选择 AI 时保留暂停状态。重复绑定同一成功回执保持会话及待办原值。

维护 AI 获取模板职责、流程、输入要求、安装目录、模板目录及实际项目配置。项目资料快照只携带路径、摘要和准备状态；正文由所选 agent 使用原生文件工具按需读取。目录概览上限 180 项，扫描上限 2,000 项、五层目录，符号链接、隐藏目录、依赖、报告、目标源码副本及常见凭据文件被排除。目录概览表示有限范围，路径缺失须结合实际检测判断。空项目从目标、输入和产出开始。

`hud_inspection.py` 使用固定只读检查：项目目录、Git 仓库范围、远程 URL 配置是否存在、工作区修改、CodeGraph 安装入口与索引状态、本地文档链接、成员职责、独立工作区根目录与资源登记。Git 远程只传递远程名称，URL 和认证信息留在本机。探针单次超时 6 秒、返回上限 256 KiB，失败标为 unknown；CodeGraph 使用公开 `status --json`，未知版本或输出格式保留待核实状态。网络连通性、实际端口可用性及正式发布状态另行核验。检测结果参与小时级后台变化摘要；用户对话立即重新读取，模型结合文档约定判断适用性。

助手正文使用现状、影响和下一步解释项目，已读取文档直接作为依据。用户的新约定经确认保存为“项目备注”，界面说明本项目助手和成员 Bot 会参考。配置卡片分别显示项目设置/向导草稿与项目备注的保存位置、当前内容和建议内容。当前内容由引擎生成，无变化项自动移除；确认前保持原值。自由回复、追问及普通解释保留待处理提案；点击“暂不处理”通过携带当前提案 ID 的 `dismiss_proposal` 明确撤下建议，过期 ID 返回 409。助手处理补充期间，提案确认返回 409，回复完成后可继续确认。

项目快照从 `workspace_resources` 表读取已保存资源，通过 `project_workspaces.selected_path` 确定成员实际目录，并按目录归并共用成员。`project.workspace_resources` 提供目录、成员、工作区 ID、配置版本及服务/浏览器/测试数据配置；未保存的目录为 `revision=0, config=null`。检测结果按实际目录区分全部已保存、部分缺失与目录归属待核实，快照读取保持只读。端口分配、默认资源生成与资源保存沿用专用流程；已登记配置与实际运行情况分别核验。

提案可以修改向导基础字段，已建项目可更新名称、简介、主目录、协作方式与工作区根目录。目录变更复用工作区配置校验、空闲保护及 Codex 目录授权同步，配置审计与确认记录一起提交。确认后详情表单同步仍与原值一致的字段，用户另外编辑过的字段保留其输入。其他目录用途、资料位置、版本与约定经确认后保存为项目备注，权威存储为项目 `settings.maintenance_facts`，后续 Bot 唤醒作为项目资料注入。目录迁移、文件重组、Git remote 设置和工作区资源变更使用各自的专用流程。

## 项目类型与资料准备

每个场景模板维护 `assistant.json`，包含输入要求、配置注意事项和启动资料的路径及用途。新建与详情使用统一字段知识，并结合模板职责、流程和真实配置引导角色、权限、成员及资源设置。`preparation` 把当前要求和逐文件检查提供给模型：`missing` 为实际缺失，`incomplete` 为正文为空或含待填标记，`needs_review` 为仍保留默认模板说明，`present` 为正文可读，截断、不可读和越界保留 `unknown`。这些状态提供检查线索，模型继续根据具体行及项目约定判断适用性和真实缺项。

助手按模板要求读取启动资料，兼容既有 `doc/` 目录。工程文档中的用户选择、UI 规范的适用范围与实际值、需求来源均纳入判断。测试项目按已有模板整理 `docs/product/PRD.md` 和 `docs/product/PROTOTYPE.md`，保留来源、版本、业务规则、验收标准、页面状态及关联编号。资料缺失和业务预期不明时明确标记待确认。

用户明确要求整理或修改文档后，所选原生 agent 读取原文、使用原生写入/补丁工具修改，再读取核验。HUD 汇报实际文件路径、修改摘要及待确认事项。长文保存在项目资料目录，HUD 展示摘要。历史 `proposal.documents` 保留确认和摘要冲突校验兼容，页面仅显示文件摘要；新轮次按原生文件执行契约处理。

已启用助手在 idle 与 waiting 状态按一小时间隔检查资料变化，新增文件和已补齐资料可触发重新检查；配置与资料摘要相同则保持原状态。后台轮次读取并报告缺项，用户明确执行指令仅用于当前轮次，完成后清除。问题与提案按现有规则持续保留。

## 使用问答依据

`usage_knowledge` 从当前程序目录的文档索引、工程和使用指南选取相关文档及章节，最多四份、共 28,000 字，携带来源路径和截断标记。它与被管理项目的 `materials` 分开提供。系统用法依据当前安装的文档和实际页面上下文回答，引用相关章节；摘录不足和外部系统行为保留待核实状态。该知识随程序的版本化文档更新。

模型上下文显式区分创建草稿与正式项目。提示约束要求目录用途提案描述实际登记能力、端口建议标注待检查、用户回答标注来源，并将模板默认约定作为待采纳建议。模型文字仍需结合实际执行结果判断；字段校验、提案确认及修订冲突由引擎强制执行。

## 存储与并发

`hud_sessions`：稳定 ID、项目归属、Bot、阶段、修订号、模型上下文代次、状态、草稿、待答问题、配置提案和确认事实。每个正式项目只有一个维护会话；草稿使用独立 ID。

`hud_entries`：追加维护发言及配置确认记录，带会话和代次。空闲重置默认 30 分钟，可设 5 分钟至 24 小时。存在待处理提案时禁止超时换代，追问和普通解释保持提案待处理；确认或点击“暂不处理”完成当前提案后，从处理时刻重新计时。无待处理提案时，下一轮在过期后换代，持久事实、用户决策与待答问题保留。模型每轮在独立维护会话中根据该代近期历史与项目快照重建上下文，额外通过 `pending_proposal` 携带完整待处理提案，提案原始发言超出历史窗口时仍可续谈。

一次超时续接只增加一个上下文代次，模型完成时刷新活动时间，避免同一轮保存结果时重复换代。

页面维护 HTTP 接口要求管理员身份。写入携带 `revision`，并发变更返回 409；模型结果按启动时的修订号比较，过期结果丢弃。切换阶段把未答问题转为待核对资料。服务重启把运行中的检查标记为失败，避免自动重复请求。后台只处理已启用会话。

`mcp/hud_server.py` 声明 `project_config` 和 `open_project_page` 两个业务入口，提供给本轮原生 agent。配置通过 `POST /hud/{id}/tool-settings` 读取及保存，导航通过 `POST /hud/{id}/tool-navigation` 请求前端打开当前项目配置；旧 `/tool-config` 保留基础字段兼容。凭据绑定 HUD ID、Bot、修订与对话代次，只允许当前运行中的明确用户请求。基础字段使用现有校验、空闲保护、目录授权同步及审计；创建向导保存草稿，详情保存项目配置。`expected_version` 为当前基础配置的 SHA-256，冲突返回当前值和新版本。工具保存保持本轮修订，`state.config_update` 的独立事件 ID 驱动表单同步；用户已经另行编辑的字段保留输入。归档项目、结束轮次和跨会话凭据均拒绝写入。

## 模型与运行

专用指令与项目资料分开传递：Hermes 网关创建会话时通过 `client_env.HERMES_EPHEMERAL_SYSTEM_PROMPT` 注入，旧版 CLI 使用隔离进程的同名环境变量；Codex 使用本次启动的 `developer_instructions` 参数覆盖。用户输入包含项目资料、检测结果、对话及当前明确执行指令。网关重试摘要同时覆盖专用指令和用户输入，保留原执行回执核对规则。

`hud_runtime.py` 复用群聊的 `hermes_gateway.enabled()` 判定：具备新版网关布局的 Hermes 通过现有 `hermes_gateway.connection()` 连接公开 `/api/ws`；旧版通过公开 `hermes chat -Q --query-file -` 子进程调用。判定依据与群聊一致，由已安装入口对应的源码布局识别，连接错误继续报告网关错误。项目助手调用链使用公开 CLI 和 RPC，执行由所选 agent 原生运行时负责。

`hud_gateway.py` 复用群聊的会话创建、恢复与传输接口。同一 HUD 会话和对话代次内，Bot、profile home、工作目录及专用系统指令保持一致时，后续轮次通过 `session.resume` 使用原 ACP 会话，保留原生 agent 缓存；每轮分别生成 submission/admission 和超时记录。首次创建使用唯一标题，HUD 空闲重置、切换 Bot、工作目录或专用指令变化后重新创建。旧格式执行记录先核对原回执，后续新轮次创建带绑定摘要的会话。

会话沿用所选 profile 的模型配置和 persona，通过公开 `toolsets: [file, no_mcp]` 选择 `read_file`、`search_files`、`write_file`、`patch` 四个原生文件工具，并以私有 editor MCP 挂载配置与导航入口；关闭 checkpoints/hooks。每轮更新配置工具凭据并检查会话空闲。宿主的工具定义缓存在会话信息阶段可能缓存缺少 editor scope 的清单，因此使用公开 `verbose: true` 让原生 agent 在实际执行作用域解析工具；私有工具轮次省略额外的 `tools.show` 查询。原生 agent 复用、执行回执和文件工具继续由 Hermes 管理。

Hermes 开启原生 Tool Search 时，配置工具可能通过宿主的 `tool_search`、`tool_describe`、`tool_call` 暴露；其可达目录仍受当前会话的 file 与单个私有配置工具集约束。该桥接由宿主按当前配置管理，业务 MCP 继续只声明配置与导航两个入口。

轮次结束释放调用租约，订阅及连接沿用群聊连接池的生命周期。profile 无活跃租约、无未决执行且空闲 600 秒后 detach 并关闭连接；再次对话恢复持久会话，agent 由原生缓存状态决定复用或重建。助手对话代次的空闲重置时间仍由 HUD 设置决定。

会话级 `config.set show_reasoning=1` 开启公开推理事件，按 session_id 过滤 `reasoning.delta`，通过现有 HUD 进度回调显示最新一行。模型与宿主决定事件是否提供；等待期间保留阶段与耗时显示。

`hud_sessions.state.gateway` 保存 request/submission/admission ID、原 profile/home、绑定摘要、提示摘要和截止时间。断线或引擎重启后，显式重试先在原 profile 核对原 admission 回执；相同输入返回原结果，新输入在对账完成后继续提交。提交确认丢失时保留会话标识并报告待核对，防止重复发起未知执行。执行预算为 600 秒，届满对排队输入执行 `prompt.cancel`，运行输入按原 generation 执行 `session.interrupt`，再核对终态，最多等待 30 秒。未确认终态继续保留原执行记录，已终止轮次之后的提交使用新的截止时间。

Codex 使用所选真实 `CODEX_HOME` 和 profile 复用认证及 Windows 沙箱运行环境，通过 `exec --ephemeral --sandbox workspace-write` 在项目目录执行。本轮参数启用原生 shell/文件补丁，关闭 apps、plugins、remote_plugin、memories 和其他 MCP，仅挂载配置 MCP；参数覆盖随进程结束释放，用户配置文件保持原值。旧版 Hermes 使用临时配置、认证副本和所选模型，启用原生 file 与配置 MCP，关闭记忆和 checkpoints，完成后清理。子进程按 UTF-8 消费输出，独立线程发送输入、读取输出和排空错误，超时终止进程树。

`scripts/verify_hud_gateway.py --inspect-only` 使用独立会话核验公开创建、工具清单与推理显示配置，全程省略模型提交。`--live` 在明确模型、服务商、域名及合成资料发送范围后验证单次提交与完成回执。验证记录包含会话标识，宿主配置保持原值；测试命令及参数见 `scripts/TEST_INDEX.md`。

`scripts/verify_hud_native_artifacts.py` 使用真实所选 Hermes/Codex 和模型，在随机回环 API、隔离 SQLite 及合成项目目录中执行。逐份读取实际 PRD、原型、工程与 UI 文档，检查来源、业务规则、页面状态及既有内容保留，并核对已建项目和创建草稿的实际配置。该脚本的文件和配置产物作为执行验收依据。`verify_hud_session_reuse_native.py` 使用原生 Hermes 网关、WS、AIAgent 和回环合成模型，单独验证文件工具会话复用、四个独立 admission、专用系统指令及连接池空闲释放。

`scripts/preview_project_hud.py` 提供独立 SQLite 和固定响应的本地交互验证服务，明确标记“本地验证”，不连接模型。其测试重置接口只存在于该脚本的预览实例。生产入口为 `python -m engine.main`。

API：`POST /hud` 创建/取得会话；`GET /hud` 待办与草稿；`GET/PATCH /hud/{id}` 读取/配置；`POST /answer` 回答；`POST /accept` 确认提案；`POST /retry` 启用或重试；`POST /bind` 绑定成功创建回执。

## 数据库配置、页面导航与 profile 创建

`project_config` 的 read/update 动作按 basic、roles、members、permissions、profiles 分区返回当前值、版本和可用操作。角色创建、改名、删除复用角色接口；成员启停和分配复用成员接口；角色权限在完整授权快照上只替换目标角色授权。项目和成员范围从当前有效助手会话确定，写入保持当前 HUD 修订，`settings_update` 提供独立事件标识。向导角色与成员列表使用 `config_update` 同步，保留已发生的本地编辑。

操作方法保存在 `hud_runtime.SYSTEM`。助手通过原生文件工具读取模板角色的 `soul_reference` 全文，将初始说明传给已有 profile 创建接口，再单独分配项目角色。创建接口仅回读本次创建的固定说明文件，返回校验结果、路径与 SHA-256；助手在宿主已授权范围内可再次原生回读。已有 AGENTS.md、SOUL 使用原生文件工具编辑。工具定义只说明业务功能和参数，工作流由原生 agent 执行。成员停用沿用原有直接授权清理和消息推进规则；角色授权按角色保留。

导航请求限于当前项目配置的 basic、agents、members、roles、permissions 标签。前端复用 `openProjectDetail` 和 `selectProjectTab`，保持当前项目未保存输入；同一导航 ID 在当前标签页去重，超过两分钟的请求保持静默。Hermes 的 tool.start/tool.complete 和 Codex 的命令/文件/MCP 事件更新 HUD 当前阶段，省略参数与结果正文。配置保存后刷新当前项目的成员、角色或权限视图，权限编辑已有本地修改时保留选择并提示服务端已更新。

成员角色字符检查提供可见转义值、从 1 起的字符位置、Unicode 码点和 role_id；名称精确筛选与当前 next_bot/role_id 派单及授权契约分别核对。
