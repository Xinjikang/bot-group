# 新建与导入项目共用七步向导

2026-10-15 更新：[向导清理与结构化迁移](PROJECT-SETUP-CLEANUP-2026-10-15.md)。旧初始化恢复界面已移除；两个入口共用七步，普通目录从头配置，完整已移除项目仅迁移结构化配置，AGENTS.md 更新且项目文档和测试脚本保留。

## 已确认的交互

新建项目沿用已验证的导入向导：项目信息 → 协作方式 → 角色设置 → 协作规则 → 成员分配 → 工作区资源 → 确认创建/导入。顶部步骤和底部操作固定，正文独立滚动；返回保留输入，配置变化后重新预览。工作区资源根据成员及协作方式生成，共享目录共用一份配置，独立 worktree 按成员配置，详情见 [工作区资源](WORKSPACE-RESOURCES-2026-10-14.md)。

- 新建第一步接受空目录或已有父目录下的新路径。发现项目文件直接提示“不能在已有项目上新建，请选择空目录或新路径”，停留第一步。允许复用仅有 `.git` 的空工作目录。预览阶段保持项目目录只读。
- 新建提供软件研发、产品调研、内容写作、产品原型设计及空白项目，基础文件必选。角色、负责人、成员和 AGENTS 编辑采用导入向导原有契约。
- 独立 worktree 自动建议同级 `<项目名>-worktrees` 根目录，支持编辑。无仓库时初始化本地 Git；空仓库时准备首次提交；已有提交时选择复用现有提交或提交选定文件。
- 第二步展示提交文件勾选和差异。依赖、构建产物及常见凭据默认排除，现有 `.gitignore` 生效。最终确认再次列出提交文件、差异、基线、提交身份和成员工作区。第四步产生的新规则变更会进入最终预览，先前明确取消的文件保持取消。
- 新建在选择 Git 后准备基础文件的首次提交；共用目录的已有项目导入保留原有“仅初始化 Git”的行为。
- 最终确认才执行目录/文件写入、Git 提交、团队授权与成员工作区准备。无成员的新建结果提示待配置团队；已选成员会创建并登记独立 worktree。

## Git 与文件边界

软件项目 worktree 模板明确要求开发成员（dev）在修改代码前，从已确认基线创建并切换到任务的 feature/<任务> 分支；续做时核对并使用既有任务分支。初始 detached HEAD 需先创建并切换分支，基线未明确时先与架构师确认，交付记录分支名和提交 ID。

第二步控件修正：新建项目以“自动生成基础文件”说明展示必需行为；导入项目保留可选复选框。向导用 `aria-busy` 区分请求期间和普通禁用状态，等待光标仅用于实际请求期间。无提交的仓库显示首次提交说明；已有提交的仓库显示两种可选基线，避免展示无法选择的选项。

第二步“下一步”完成 Git 检查后直接进入角色设置，检查失败时保留当前页并显示原因。用户可通过“重新检查 Git 和提交范围”在本页查看勾选范围，也可返回本页调整；最终确认页继续展示完整提交范围及差异。

`project_setup_git.py` 生成只读基线计划。文件指纹、基线提交和分支随配置纳入确认摘要，提交前重新核对。首次提交使用 `Project Setup <project-setup@localhost>`，新初始化分支为 `main`；模板中的发布分支流程保持项目约定。远程仓库和用户全局 Git 配置保持原状。

提交通过临时 index、`commit-tree` 和 `update-ref` 的旧值校验进行，跳过 hooks。只有确认的路径写入提交；真实 index 中其他已暂存内容保持原状。工作区从确认的提交创建，初始为 detached HEAD，任务执行时按项目规则建立工作分支。沿用旧提交时，主目录的新文件、规则编辑及其他本地修改保留在主目录，独立工作区使用界面展示的旧基线。

失败时回滚数据库，清理本次未被外部修改的基础文件和干净 worktree，按旧值校验恢复分支与 index。已经生成 Git 对象的初始化会保留完整的空仓库，重新检查后可复用；发生外部并发修改时保留外部结果。跨 Git、文件系统和 SQLite 的操作没有统一原子事务。

## 操作记录与恢复

`project_setup_requests` 保存请求标识、确认配置和最终结果，`GET /projects/setup-progress/{request_id}` 供管理员查询。相同请求重发返回同一结果，修改请求内容要求重新预览。运行期间展示真实阶段，当前窗口可查询提交结果。刷新后重新选择目录，已完成登记的项目直接打开。

普通失败后从协作方式重新检查，重新确认生成新的请求标识。重新打开向导从头配置；第一步清理可证明归属的旧初始化残留。当前提交的结果查询继续使用持久化请求编号。

## 实现入口

- `frontend/project_import.js`：新建与导入共用页面、Git 范围、进度与恢复。
- `engine/project_setup_history.py`：旧初始化残留清理与完整已移除项目的结构化配置读取。
- `engine/project_import.py` / `project_import_files.py`：新建目录校验、模板计划、事务及发布。
- `engine/project_setup_git.py`：Git 范围、提交、worktree 与失败恢复。
- `engine/project_setup_progress.py` / `schema.sql`：持久化操作结果与实时阶段。

## 确认页角色摘要

新建与导入的最终确认页按角色展示角色权限、已选成员数量和名单。零权限显示“无管理权限”，零成员显示“未分配成员”；成员明细使用“个人附加权限”，为空时显示“无附加权限”，区分角色授权与成员配置。
角色设置卡片标题保持“项目负责人”，同一行右侧用小字显示职能“接收阻塞通知”。确认页在“角色：项目负责人”下方单独显示“固定职能：接收阻塞通知”，随后列出角色权限和已选成员。脚本入口版本为 20261015-owner-fixed-duty。

第五步统一选择成员并分配角色。“项目负责人”角色同时承担需求管理和接收任务阻塞通知的职责，只需在角色下拉中选择一次。引擎从该角色的成员推导通知对象；同一项目最多一人，改选其他成员时清除原成员的负责人角色，改换角色或取消成员时同步清除通知对象。额外负责人复选框、顶部负责人下拉和确认页重复负责人条目均已移除。未指定负责人仍允许创建，界面不增加缺失提示；通知沿用既有回退规则。
