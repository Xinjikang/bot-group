# 项目向导清理与结构化配置迁移

本文更新 PROJECT-SETUP-WIZARD-2026-10-14.md 的旧初始化恢复约定。

## 当前行为

- 保留新建和导入两个入口，共用七步向导。新建、普通目录导入和初始化残留重新配置。
- 第一步读取目录前，通过管理员接口 `POST /projects/import/prepare` 清理可证明归属的旧初始化残留。已登记活跃项目直接打开；已归档项目仅提示归档状态。
- 导入仅从同目录下 `removed=1` 且 `readiness_status=ready` 的完整历史项目载入结构化配置。多个历史记录取最近移除的完整项目；原项目及业务历史继续保留。
- 迁移字段为名称、简介、模板类型、协作方式、worktree 根目录、角色及权限、有效成员及个人授权、可定位的工作区资源和 Git 基线选择。模板使用当前版本，用户手动选择的模板优先。各步继续按当前规则校验并允许调整。
- 新建保持从头配置。旧初始化表单、三步界面、独立进度窗口和刷新后续填旧草稿入口已移除；当前提交仍有幂等请求编号、进度查询和丢响应后的结果查询。

## 文件保护

AGENTS.md 在当前向导中按新模板生成，最终确认时沿用原文件指纹校验、备份及原子替换。用户可在第四步检查和编辑新规则。

已有项目文档、测试脚本、README 和源码保留原始字节；模板只补齐缺失文件。导入已有项目完成后提示检查 AGENTS.md 和已有文档中的角色、流程、目录约定。与当前模板同路径且内容不同的 Markdown 文档另列清单；内容差异用于提醒人工核对，程序不据此判定语义冲突。

2026-10-16：完成提醒限定为 `creation_mode=import`（旧客户端省略时默认导入）。`creation_mode=new` 的软件、调研、写作及空白模板完成时省略 `review_reminder`，首次响应、幂等重放与进度查询结果采用相同规则。新建流程保留第四步的 AGENTS.md 人工核对。

提醒范围的回归入口为 `scripts.test_project_setup`、`scripts.test_project_setup_history`、`scripts.test_import_agents_edit`，使用临时项目及隔离数据库。

残留清理仅处理旧初始化记录明确归属的规则文件和精确暂存路径，删除前检查路径边界和摘要；已发表的文档、脚本及源码保留。规则文件被用户修改时也保留，交由最终确认时备份替换。清理失败可重入；文件系统和数据库间无跨介质原子事务。原记录标为 discarded，旧提交/重试接口拒绝重新执行。占用中的项目、归档项目、完整项目及缺乏归属证据的未就绪项目均受门禁保护。

已清理的初始化目录可保留文档及测试成果后从头配置；普通有内容目录继续使用导入入口。

## SOUL 参考
