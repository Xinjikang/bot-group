# 协作入口与网页设置

## 消息处理

系统提示词与 MCP 工具说明共同规定消息闭环。要求回复的 work 来信先通过 `group_send` 实质回复并 @ 原发送者，确认发送成功，再用收到的消息 ID 调用 `group_mark_seen`。明确无需回复的点对点来信处理完成后可直接确认已读。检查 `seen` 和 `blocked`，被阻止的来信仍保留 pending；每批完成确认后再读取下一批。

chat 的成功发言或允许的跳过自动清理本话题未读并完成轮次；手动已读工具用于点对点。普通最终回复文字不会发送到协作系统。收件箱为空时依据唤醒来源检查任务或需求，没有可执行工作则结束；读取错误按返回原因处理。

这些规则补齐工具协议。反复唤醒且持续读空仍需结合部署版本、执行身份、项目、话题窗口和调用记录定位；漏标已读会保留 pending。

## 项目规则加载

`project_rules.prompt()` 在每次唤醒构建系统提示词时读取项目主目录 `AGENTS.md`，提供路径、SHA256 和正文，独立于人格文件与宿主的上下文发现。Hermes 通过本次进程的 ephemeral system prompt 接收，Codex 通过 developer instructions 接收；恢复的会话取得本次快照。正在运行的执行在下一次唤醒时获得更新。

正文超过 16000 UTF-8 字节时，为控制 Windows 命令与环境大小，注入路径和版本，并要求本轮完整读取文件。文件缺失、空白、编码错误或读取失败时，提示仅进行规则核查和沟通，待负责人补齐规则后实施。worktree 继续使用现有受管理 override 同步及冲突保护。

实施前按项目流程确认需求、任务与执行人已落库，有管理权限者创建和拆解，执行成员领取后工作，交付通过任务节点流转。讨论与咨询按其授权范围回应。项目规则独立于 SOUL 选择生效；宿主文件执行工具的逐步行为仍依赖模型遵循规则，任务管理 API 保持既有权限、执行身份和流程校验。

## 角色与协作规则一致性

创建和导入向导在删除角色前弹窗说明成员关联、派工、审查和验收影响；确认后移除角色并清空对应成员角色。调整角色权限后弹窗提醒核对职责与交接约定，同一角色卡片中的连续权限调整只提醒一次。

角色变更沿用规则页的人工确认流程，已有正文编辑保留。正文中的角色引用由用户自行维护，允许保留原文并继续保存；前后端均无基于角色引用的新增保存拦截。

## 创建 profile

`POST /profiles/create` 支持省略 project 或传空字符串：创建独立宿主目录并注册 Bot，返回空 `member_profile`，保持幂等重试与失败回滚。传有效 project 沿用创建并加入路径。创建权限仍限管理员。

创建/导入向导复用成员创建弹窗，创建成功后加入本次候选和选中成员；最终确认项目时再配置角色、项目授权与目录。取消项目向导保留独立 profile。Codex 在独立创建时采用现有沙箱和智能审批默认值，目录授权在正式入组时配置；Hermes 保留配置来源、认证与个人指令选项。

## 更新检查与设置

`GET /system/version` 返回程序根 `VERSION`；缺失时显示开发版。`GET /system/update-check` 复用安装器的 `RELEASE_INDEX_URL` 和正式版本索引，只比较正式发布的数字版本，校验发布资产字段，返回当前版本、最新版本、更新状态及检查时间。未知当前版本保持显式未知状态。两个接口沿用用户身份校验。

网页每次打开并取得用户身份后检查一次，每 12 小时再次检查；恢复可见或获得焦点时补查已到期检查。并发请求合并，服务端同一版本和发布源缓存 60 秒。网络失败在关于界面显示，可手动重试。检查只读取发布元数据，升级继续由维护者使用现有脚本执行。

顶栏更新提示位于称呼前。设置收纳称呼编辑、背景、主题、重启和关于。成员启停胶囊沿用现有启停接口和授权行为。

## 验证与生效

回归入口见 [测试索引](../../scripts/TEST_INDEX.md)。覆盖正式版比较与失败、角色变更弹窗及保留原文保存、无项目创建再入组、规则逐次加载、消息门禁、真实浏览器的定时/恢复检查及页面刷新。测试使用隔离宿主、SQLite 与 Git，发布源使用模拟索引。

更新后由维护者重启引擎并刷新页面；持有旧 MCP 的宿主需重新加载，Hermes 网关需重启。既有 Bot 在下一次执行获得新的提示词和项目规则快照。
