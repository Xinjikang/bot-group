# 服务重启按钮与超时收尾

## 行为

右上角顺序为背景、切换主题、重启服务、连接状态。管理员确认后暂停新执行，等待当前 Bot 自然结束最多 120 秒；超时进入 `terminating`，由引擎终止剩余 Bot 进程树并等待执行收尾，再回收登记的 browser-harness 资源，最后退出服务。排队任务与当前话题发言位保留，启动恢复继续处理。

Windows 进程树处理参考 `0c8a604` 之前的 start.sh：沿允许的启动器父链回溯，使用 `taskkill /T /F` 清理整树。新版从精确会话匹配的 Bot PID 起步，以该次执行登记的启动器 PID 为上限；引擎自身及宿主祖先受保护。使用原生进程快照读取父子关系，核验快照中的后代退出。匹配未知、树终止失败、执行收尾失败或浏览器清理失败会返回明确失败并恢复入口，保留现场供处理。

`engine.lifecycle` 拥有全部执行停止和资源回收逻辑；`stop_engine.py` 负责发出管理员退出请求、确认原进程与端口释放。后台重启助手 `tools/restart_engine.py` 调用现有 `start.bat`，继续复用环境检查、停止、后台启动和健康检查。助手以独立隐藏进程运行，旧引擎退出后仍能继续。

三个等待范围分别为：引擎等待 Bot 自然结束最多 120 秒；停机客户端默认等待退出 180 秒；页面每次进入重启轮询最多等待 300 秒，刷新恢复同一操作时重新计时。页面超时后应检查回执及日志，再按当前实例状态处理。服务尚未起来时，回执文件可在数据目录直接查看。

## 接口与回执

- `POST /admin/restart`：管理员鉴权，返回 202 和操作 ID。同一进行中的重启复用同一操作，避免重复启动助手。
- `GET /admin/restart`：管理员读取回执与当前退出阶段。
- 回执、日志分别保存到有效数据目录的 `logs/service-restart.json`、`logs/service-restart.log`；回执使用临时文件原子替换，跨引擎保留。
- 助手继承当前生效的 host、port、数据目录、数据库及附件目录，并用旧 `instance_id` 限定停机目标。这个单次停机标记在启动新引擎前移除。
- 仅在健康检查通过、实例 ID 更新且程序根与数据库匹配时记录成功。助手失败或异常退出会显示失败；服务无法恢复连接时，页面超时提示查看日志。

前端保存本次操作 ID，刷新后恢复 GET 轮询；重启期间禁用按钮。网络断连保持等待，新实例验证后重连 SSE、刷新数据并保留当前页面选择。登录隐藏控制按钮，后端独立执行权限检查。

## 验证范围

- 真实 Windows 三层子进程终止与无关兄弟进程保护。
- 真实超时退出链路：隔离数据库登记模拟执行与本地 IPC harness，等待时间设为 0，验证引擎终止执行、落库结束状态、关闭 harness、删除资源登记，最后发出退出回调。
- 真实 Windows 临时程序目录（含空格）、临时数据库和随机端口，连续两次通过 API→后台助手→start.bat→停止/启动→新实例健康检查；验证旧 PID 退出、数据库内容保留及助手退出。仅 install.check 使用成功替身，其他启停链路均为真实执行。
- Chrome 使用合成 HTTP 验证按钮顺序、取消、重复请求防护、阶段反馈、刷新续查、新实例门槛、失败和登录隐藏；顶栏截图保存于 `cache/service-restart-topbar.png`。
- 单元回归覆盖管理员鉴权、配置/实例绑定、失败传播、超时状态机和话题退出保护；相关回归命令见测试索引。

执行结果与截图保存到项目主目录测试报告。测试中的进程查询始终绑定隔离夹具。

引擎代码更新后由用户手动重启并刷新页面。首次从缺少此接口的旧版本升级时，新前端访问旧后端会收到 404。
