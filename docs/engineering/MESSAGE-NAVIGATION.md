# 底部消息导航

## 交互

- 输入区上方固定预留 42px，同一行中间为“回到底部”，右侧为“有人 @你 · N”。按钮独立显示，不随另一按钮出现/消失而移动。
- 距底部至少 80px 时显示“回到底部”。点击滚到最新消息，保留 @队列。
- bot 消息的结构化 `mentions` 包含 `user` 时加入待查看队列；普通文字和用户自己发出的消息不计数。
- 群聊总览显示本项目的待查看数，话题视图显示本话题的待查看数。
- 工作群总览与 chat 话题页共用底部导航行，均支持回到底部和 @消息定位。
- 点击 @按钮按消息 ID 从小到大定位，展开折叠的话题，必要时加载历史页，定位成功后减一。隐藏话题通过进入话题查看，原隐藏设置保持不变。
- 自动已读：页面位于前台且窗口获得焦点，无打开的对话框，消息至少一半进入消息区并连续停留至少 1 秒后清理；超高消息按消息区高度的一半判断。折叠、屏幕外、后台消息保留。刷新、滚动、折叠/展开和窗口尺寸变化都会重新判定。
- 工作群和话题按项目共用消息 ID 队列。话题内查看后工作群同步减少；在工作群展开话题并查看后，话题同步减少。切换视图中断尚未完成的可见停留计时。
- 按钮定位期间禁用重复点击。接口失败、消息暂时无法显示或用户切换视图时保留待查看记录。点击时复核已撤回或已删除的消息并清理记录。

## 状态与边界

`frontend/message_navigation.js` 使用当前站点 localStorage 的 `ge_mentions_v1:<project>`，保存扫描游标和待查看消息 ID/话题 ID。刷新、切换话题和项目后保留；清除浏览器存储会重置，跨浏览器/设备不共享。

首次启用从该项目最新 100 条消息建立提醒。此后按已保存游标补齐新增消息，每批最多 500 条；浏览器关闭期间新增的消息会在下次打开时补齐。初始项目为空（游标为 0）时使用现有无 limit 的正序接口，避免接口的最新页语义跳过消息。

该队列独立于 bot inbox 和现有话题已读标记。点击定位或满足前台可见条件作为查看确认；返回底部只会清理实际进入可视区域并停留的消息。已确认消息不会因话题全量轮询再次出现。

前端更新后刷新页面加载新脚本。
