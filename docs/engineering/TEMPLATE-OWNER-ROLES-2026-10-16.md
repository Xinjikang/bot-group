# 模板负责人身份、名称与权限

每个场景模板通过 manifest 的 owner_role_id 指定负责人角色，名称、职责和默认权限由该角色定义。负责人身份统一负责项目通知对象的选择，各模板使用自己的角色名称。

| 模板 | 负责人名称 | 默认管理权限 | 其余角色 |
| --- | --- | --- | --- |
| 软件研发 | 项目负责人 | 5 项需求管理权限 | 架构师保留 5 项任务管理权限，执行角色沿用原配置 |
| 产品调研 | 调研负责人 | 10 项需求和任务管理权限 | 资料研究员、分析员、复核员均为 0 项 |
| 内容写作 | 主编 | 10 项需求和任务管理权限 | 资料研究员、作者、审校均为 0 项 |
| 产品原型设计 | 产品经理 | 10 项需求和任务管理权限 | UX 设计师、原型工程师、原型评审员均为 0 项 |
| 空白项目 | 项目负责人 | 5 项需求管理权限 | 用户自行添加 |

新建和导入预览返回 owner_role，向导按此名称展示固定职能、保护角色、约束唯一负责人、生成确认摘要及 owner_bot_id。服务端根据所选模板独立校验负责人角色和人数，并从角色成员推导通知对象；默认权限仍可由用户调整。调研/写作的任务定义由负责人维护，执行角色依靠任务归属完成领取、阻塞、产出和交接。

创建项目时，将本项目的负责人角色实体 ID 保存到 settings.owner_role_id；角色与权限接口统一返回 is_owner，项目设置按此标记保护负责人角色。角色改名保持身份，通知仍按已配置 owner_profile 投递。旧项目沿用既有配置，缺少标记时兼容原“项目负责人”角色。

历史项目重新导入时，草稿将已识别的负责人角色映射到当前模板名称；同名合并保留历史授权并集。成员归属随角色名称映射；如果合并后有多人担任负责人，提交校验要求用户在成员步骤重新选择唯一负责人。历史项目和文档原件在最终确认前保持原样。

AGENTS.md 使用 ROLE_LEAD/ROLE_EDITOR/ROLE_PM 引用场景负责人，明确项目统筹、阻塞通知、任务定义维护及执行成员零管理权限。SOUL 名称、职责与 README 版本同步。旧预览需重新加载模板。

相关测试见 [测试索引](../../scripts/TEST_INDEX.md) 的项目模板与角色分类，使用临时数据库、项目目录及隔离浏览器。引擎代码需手动重启生效，随后刷新页面并重新打开向导。已有项目的名称和授权保持原配置。
