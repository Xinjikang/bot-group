# Web 升级契约

管理员在“关于”手动检查更新；右上角提示和“关于”的升级按钮共用确认框。检测保留首屏、12 小时周期和休眠恢复补查，手动检查绕过周期限制。界面在明确确认后发送升级请求。

## 接口与执行

- `GET /system/updates`：当前身份、最新正式版本、`update_available`、`can_upgrade` 及 `upgrade_blocked_reason`。Git 工作区、未知版本或缺发布清单时说明更新边界。
- `POST /system/upgrade`：管理员提交 `request_id`（32 位小写十六进制）与确认的 `version`，返回 202 及持久回执。服务端重查正式源，目标版本发生变化则返回 409，要求重新确认。下载 URL、摘要和清单均由服务端解析并固定。
- `GET /system/upgrade`：管理员读取回执，响应禁止缓存。回执包含请求 ID、阶段、目标版本、安装目录与数据库绑定、助手进程和新实例标识，以及失败说明。

`engine/app_upgrade.py` 通过共享维护锁与重启协调，同一活动升级及同一请求 ID 复用回执。`tools/update_engine.py` 使用虚拟环境之外的基础 Python，独立于旧引擎执行。程序、数据目录和端口取发起实例的有效配置。回执与日志位于数据目录 `logs/app-upgrade.json`、`logs/app-upgrade.log`。

升级复用 `tools/upgrade.py`：固定目标下载及摘要/清单校验、安全停机、SQLite 和程序备份、文件清单落地、依赖同步、迁移副本检查、就绪校验。完成后运行安装目录的 service 入口并核对健康、实例变更及程序/数据库路径。新服务启动失败时核对升级备份的目标资产，恢复旧版并启动；回滚失败时保留证据并报告。

## 连接与失败

前端在提交前保存请求 ID；POST 响应丢失后通过回执核对，保留单次提交。升级期间暂停 SSE 重连，并用短请求轮询状态；服务退出期间显示等待恢复。页面刷新后从 sessionStorage 或服务端活动回执继续监控。完成时核对新实例与目录绑定，提示刷新界面。每次监控最多等待 30 分钟，超时保留请求以供再次核对。

服务停止期间，页面无法读取新的进度，显示断线等待状态；服务恢复后读取最终回执。服务无法恢复时使用本地日志排查。首次上线此功能需管理员重启引擎并刷新前端，后续包含该功能的 Release 安装可从界面发起升级。

## 验证

单元测试覆盖鉴权、目标变更、Git/清单边界、独立解释器、重复提交、升级与重启互斥、助手退出和恢复分支。隔离 Windows 安装运行真实 API、独立助手、版本归档校验、数据库备份/迁移、服务启停及健康检查；依赖安装使用受控夹具。浏览器覆盖手动检查、两个确认入口、取消、响应丢失、刷新续查、结果与窄屏主题。命令见测试索引。
