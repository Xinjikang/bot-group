# Bot 执行异常反馈

进程启动失败、准备阶段异常、非零退出和执行超时由引擎在所属项目及话题内写入系统通知。通知使用 Bot 显示名称和统一分类文案；有触发消息时保留父消息与轮次。用户主动停止及服务停机沿用现有反馈，成功退出保持静默。

| 分类 | 群聊提示 |
| --- | --- |
| configuration | 配置不完整或无效，请检查配置。 |
| authentication（401） | 身份认证失败，请检查凭证。 |
| permission（403） | 访问被拒绝，请检查权限。 |
| rate_limit（429） | 请求受限，请稍后重试或检查配额。 |
| capacity（模型容量已满） | 所选模型容量已满，请稍后重试或切换模型。 |
| timeout | 请求超时，请稍后重试或检查超时设置。 |
| network | 连接失败，请检查网络设置。 |
| upstream（5xx） | 服务暂时异常，请稍后重试。 |
| unknown | 运行异常，请查看日志。 |

`engine/execution_errors.py` 使用有序错误特征匹配分类，无法识别时采用 unknown。Hermes 使用退出输出尾部，Codex 使用已收集的 JSONL 尾部。JSONL 分类优先使用最后一条有效 `turn.failed` 的错误消息，其次使用最后一条有效 `error` 消息；缺少这些事件时沿用文本分类。明确的模型容量错误归入 capacity，其余文本按既有顺序匹配。工具输出中的源码、配置关键词和历史错误保留在脱敏诊断中，明确失败事件决定通知分类及专用提示。分类提示隐藏供应商、变量名和原始异常文本。

`execution_errors` 以 `(project, profile, attempt)` 为主键保存类别、脱敏诊断、退出码与消息 ID，与通知在同一事务提交。消息通过 `message.new` 实时通知，刷新后从正常消息接口恢复。同次执行重复报告复用消息；通知仅进入用户收件箱，保持话题发言位、任务状态和 Bot 收件箱原样，避免异常消息触发新的模型调用。任务重试继续按既有策略执行，公开的任务失败说明采用同一分类文案。

诊断进入数据库专表和引擎日志，输出长度受限。脱敏覆盖父环境中的凭证、profile 文件中的凭证及自定义 key_env 引用、Bearer、凭证赋值和 URL。群聊消息仅含固定文案。排查日志位于数据目录 `logs/engine.log`，测试使用合成凭证和隔离数据库。

升级后手动重启引擎创建新表，再刷新页面。验证命令见 [测试索引](../../scripts/TEST_INDEX.md)。
