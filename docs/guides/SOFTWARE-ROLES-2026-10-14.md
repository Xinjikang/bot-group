# 软件项目默认角色精简

软件模板用于新建和导入，版本以 manifest 为准。已登记项目的角色及授权保留。

工程约定由 Bot 持续维护：架构师负责版本、基线、分支及集成信息，开发维护实际技术配置，项目负责人维护项目约束；在换版、方案变更、合并及发布交接时更新并提交。工程表列出默认约定、实际值及维护职责；测试账号等仍支持用户手工编辑或通过对话授权 Bot 更新。方案取舍依据写入 `docs/design/`，技术文档直接描述确定的方案、依据与约束。

测试报告统一保存到**项目主目录** `reports/tests/<release版本>/<日期>-req-<测试需求ID>/REPORT.md`，入口为报告索引，相邻 `evidence/` 保存证据。shared/worktree 成员使用引擎注入的“项目主目录”拼接上述路径，交接记录报告绝对路径、被测提交、结果及遗留问题。报告保持本地；需求、设计、技术文档、可复用测试和用例索引在当前工作区随分支提交。具体规则见 [文档存放约定](DOCUMENT-STORAGE.md)。

- 删除独立协调者角色，以项目负责人统一管理需求（req.create/update/resume/complete/cancel）；导入默认配置只出现一次项目负责人。
- 架构师拥有任务创建、更新、恢复、关闭及撤回权限（task.create/update/resume/complete/cancel），开发任务在自测、独立审查、合并及验收后关闭；项目负责人在全部开发任务完成后关闭开发需求。
- 整个 release 开发合并完成后，用户发出测试指令，项目负责人创建独立测试需求，架构师拆解测试任务，测试员执行并提交报告。测试发现问题只记录报告，修复及复测等待用户后续明确指令。架构师按报告交付验收关闭测试任务，项目负责人关闭测试需求，版本质量结论单独标注并作为发布依据。
- worktree 约定包含从 main 建立 release 基线、feature/<任务ID>-<模块>-<功能简述> 与 fix/<任务ID>-<问题简述> 命名、设计进入基线、精确提交审查、同仓库本地交接及按约定远端同步。
- 项目按开发 → 测试 → 开发 → 测试逐轮推进。用户依据报告发出修复指令后，项目负责人新建开发需求，经过拆解、开发自测、审查、合并验收；下一轮版本测试由用户单独发令并新建测试需求。
- 前后端开发、审查员、测试员默认管理权限为空。task_log 沿用任务持有、任务状态及交接成员角色校验，无需 task.update。
- 工作流程、共享/worktree 生成内容及 SOUL 参考同步；实际 Bot 配置保留。

验证：模板、角色改名和导入补齐单元回归；真实 Chrome 新建与导入向导验证。流程用例覆盖撤去 task.update 后领取、记录和交接。

用户手动重启引擎后刷新页面，重新选择软件模板以加载新版默认配置。
