# 模板工程基线

软件模板将协作流程放在 AGENTS，需求、设计和工程约定在当前工作区 docs 中分类提交，可复用测试与运行条件放在测试索引。审查与验收结论写入任务节点，测试及技术调研报告按 [文档存放约定](DOCUMENT-STORAGE.md) 保存到主目录 reports 的对应分类。

## 工程约定

软件模板生成 `docs/ui-spec/UI-SPEC.md`，收录可调整的视觉变量、组件状态、响应与可访问性基线。已有品牌和组件库由前端成员登记实际约定，审查员按采用的规范版本核验。UI 文档随分支提交，导入时保留已有文件。

- 开发前明确设计与验收依据，复用已有测试；自测后更新技术文档、提交代码并记录交接信息。
- shared 模式约定串行修改与交接；worktree 模式约定基线、任务分支、集成验证和清理。实际技术栈、远端、版本和资源由项目维护。
- CodeGraph 按项目选择启用，工程文档登记版本与更新命令。测试资源采用引擎分配的端口、浏览器及数据目录，现场结果单独留档。
- task_log 的参数和授权契约放在工具说明；SOUL 参考聚焦角色职责、专业能力及工作风格，用户通过引用与保存管理实际 profile。

## Git 操作边界

软件模板在 shared 与 worktree 模式下均要求切换和合并前检查暂存、工作区及未跟踪改动，以及未完成的 Git 操作。本人当前任务按续做处理，其他归属先保留现场并协调；stash、丢弃改动、强制切换、重置分支和改写共享历史按改动归属及项目授权处理。模板提供只读状态检查命令。

worktree 任务分支创建和切换前核对任务归属、交付提交及占用情况，同名异任务和跨 worktree 占用由架构师协调。审查员按准确提交 detached 检出；架构师将审查通过的提交作为合并对象，新增提交、历史改写和冲突解决产生的变更补充审查及相应验证。

配置远端的项目在工程文档登记远端名称、同步方向、权威分支和分叉处理方式。同步时先 fetch 并核对提交关系，分叉或约定缺失交架构师协调；强制推送按项目授权执行。

## 模板维护

调研、写作和产品原型的独立 worktree 使用 `task/<任务ID>-<阶段>` 分支，从确认基线或上游交付提交开始，由各模板的负责人协调基线与合并，复核或评审成员检查准确交付提交。生成规则使用项目实际角色名称；成果交接、返修和验收沿用各场景流程。新建与导入预览使用当前模板规则，已登记项目的文件及历史初始化快照按原有保留机制维护。

模板版本随 manifest 更新，预览与文件发布共享摘要校验。旧初始化快照保存原内容，当前模板参考按模板类型读取；已有项目的文件迁移与规则更新由显式操作完成。

验证使用临时 HTTP/SQLite/Git：两种目录模式、角色改名、预览到落盘一致、快照恢复、宿主配置保护与模板链接。浏览器覆盖向导、SOUL 参考及窄屏，MCP 握手核对工具描述。入口见 [测试索引](../../scripts/TEST_INDEX.md)。
