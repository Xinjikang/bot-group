# 在 ECS 安装并接入远程 Hermes

在目标 Hermes profile 安装 relay 插件后，管理员可从办公机的「设置 → 远程节点」配对。按两台机器之间可达的网络方向选择由哪一端发起连接。远端成员名由插件从当前 profile 读取。

已配对的节点可在「设置 → 远程节点 → 删除节点」移除。确认后会断开连接、清除配对及来源绑定、停用各项目中的旧成员，并保留历史消息和任务。请先结束该节点仍在进行的执行。再次添加同一远端 profile 时，引擎分配新的成员标识。

两个拨号方向均使用 WSS。办公机和远端 Hermes 首次启用各自的监听时自动生成自签名证书，重启后复用。配对命令或链接携带监听端证书的 SHA-256 指纹，拨号端在发送邀请或凭据前核对指纹。

升级旧 WS 节点时，先更新办公机引擎和远端插件，再在原节点办理迁移。云端连本机时点击“重新签发”，在原 Hermes profile 执行含 `--fingerprint` 的完整命令。本机连云端时，在原节点更新插件生成的 WSS 配对链接。原成员标识、项目绑定和消息历史继续使用。更换证书后需重新核对新指纹。

### 离线后的重连

引擎主动连接插件时，每次拨号都建立新的 TLS 连接并核对已保存的证书指纹。插件监听端关闭 TLS 1.3 会话恢复票据，以避免同步 WebSocket 的升级握手偶发超时。

已配对节点由选定的一侧拨号。对端关机、网络中断、建连超时或等待认证回执超时都会触发同一套重试。首次失败后最多再拨 24 次，依次等待 1、2、4、8、16 秒，再等 19 次 30 秒。固定等待共 601 秒，实际时间另加建连和握手耗时。认证成功即结束本轮，下次掉线重新计数。

| 连接方向 | 停止后的恢复入口 |
| --- | --- |
| 本机连云端 | 在办公机「设置 → 远程节点」打开节点的「切换方向」，保留「本机连云端」，点「重试连接」。页面显示本机实际拨号状态和原因。 |
| 云端连本机 | 通过独立于 relay 的渠道私聊云端 Hermes，说「重连」。工具 `bot_group_reconnect` 使用保存的配对；同一 profile 配对多台引擎时指定引擎地址。私聊说「查看 relay 状态」可查询本地停止原因和尝试次数。办公机断链期间只显示离线。适配器停止后，私聊查询显示离线。此时说「重连」会保存请求，待适配器启动后拨号；认证完成才显示在线。 |

Hermes 网关管理私聊准入。插件在私聊中提供查询状态、注册、监听和重连工具。重复请求复用同一轮拨号，在线时沿用原连接。超过重试上限后，恢复网络的一方需等发起端手动重连。凭据拒绝、证书校验失败、协议或 MCP 不兼容、来源受限会立即停止，请按原因修正。关闭码 4005 表示方向不符，核对已保存的方向及切换目标，恢复后由选定的一端发起。日志在首次失联时记录原因，在恢复、明确拒绝或耗尽时汇总拨号次数、离线时长和各原因次数。

## 1. 前置

- ECS 已安装 Hermes gateway 和支持 `venv` 的 Python 3.11+。单文件安装器通过目标 profile 的 `hermes config path` 定位安装目录。手动解包时，将 `HERMES_HOME` 指向同一 profile 的目录。
- 办公机引擎和插件都需要包含首次接入功能。办公机更新源码后由管理员重启引擎、刷新页面。
- 选择与办公机引擎有共同通信协议的插件，核对制品来源和校验值。

## 2. 安装

推荐使用 [README 的一行安装命令](../../README.zh-CN.md#接入远程-hermes)。已有配套 `install-relay.pyz` 时，在 ECS 执行 `python3 install-relay.pyz` 即可安装到当前 profile；指定 profile 使用 `--profile <名称>`。按输出重启对应 gateway。

手动安装时将归档和配套的 `SHA256SUMS` 放在同一目录，运行以下命令，将 `archive` 设为实际交付的文件名。校验通过后再解包、安装随包 MCP 的依赖并启用插件。

```bash
(
  set -eu
  archive=bot-group-relay-v0.2.16.tar.gz
  plugin_dir="${HERMES_HOME:?请设置目标 profile 的 HERMES_HOME}/plugins/bot-group-relay"
  expected=$(awk -v file="$archive" '$2 == file {print $1}' SHA256SUMS)
  printf '%s  %s\n' "$expected" "$archive" | sha256sum --check -
  mkdir -p "$plugin_dir"
  tar -xzf "$archive" -C "$plugin_dir"
  "$plugin_dir/install.sh"
  hermes plugins enable bot-group-relay
)
```

## 3. 配置

首次接入在办公机设置中打开“远程节点”，选择“添加远程 Hermes”。

- 云端主动连接办公机时，选择“云端连本机”。选取云端可达的办公机网卡并启用监听。使用 Tailscale 时选择办公机的 Tailscale 地址。在目标 Hermes profile 下运行页面生成的邀请命令，保持命令运行，回到页面核对成员和来源 IP，再点“确认添加”。插件读取该 profile 的实际身份。重新配对时可保留环境中的旧凭据，页面生成的新邀请优先。确认后，终端显示配对已保存即可关闭。
- 办公机主动连接云端时，在目标 profile 运行 `hermes bot-group-relay listen --address <云端网卡地址> --port <监听端口>`。将输出的配对链接粘贴到“本机连云端”，核对经验证的成员与短证书指纹并确认。主窗口显示该节点的实际连接状态。

两端可以使用同名 profile。本机显示原名（如 `default`），远端显示 `default（远程）`，多个同名远端通过括号内的序号区分。确认后，在项目的成员选择器中按显示名选择对应节点入组。

“云端连本机”换发凭据时，点原节点的“重新签发”，复制弹窗中的整条命令发给远程 Hermes 执行。命令指定宿主 profile、引擎地址和一小时有效的一次性邀请。引擎核对该节点的 profile 和已绑定来源后更新凭据。取消或过期时保留原凭据状态。页面提示新凭据生效且远端显示“配对已保存”即完成。运行新版插件的网关下次连接时读取新凭据。

带邀请的 `register` 收到确认后保存引擎地址、当前 profile 和长期凭据，然后退出。同一 Hermes profile 下再运行第二台引擎的邀请命令，即可同时接入。运行中的适配器会发现新配对，重启 gateway 后会分别恢复连接方向。

原配对保存在插件目录的 `state/pairing.json`，新增引擎的记录分别保存在 `state/peers/` 下。升级前已被覆盖的配对，可在对应引擎的原节点上重新签发邀请。群聊工具使用会话所属引擎的地址或代理。两台引擎需要独立检出同名项目时，在节点卡中分别设置协作根目录。

两台引擎都主动拨入 ECS 时，在 ECS 上为每台引擎选一个监听端口。为已通过邀请接入的引擎准备反向监听时，运行 `hermes bot-group-relay listen --address <云端网卡地址> --port <该引擎的监听端口> --engine-url <原邀请中的引擎地址>`，把链接导入对应节点。

**配置协作根目录。** 在远程节点卡片填写 ECS 用户可写的绝对路径，例如 `/srv/projects`，点“验证并保存”。在线插件创建或验证目录并测试写入。每个节点配置一次，适用于该节点参与的各个项目。ECS 需要 Git，以及访问项目 origin 的权限。项目 origin 使用 HTTPS 或 SSH 地址，认证由 ECS 上的 Git 管理。

成员加入项目后，插件在协作根目录下建立以项目 ID 命名的仓库。共享主目录模式使用这个仓库的 `master`。独立 worktree 模式在这份仓库上创建 `bot-group/<成员标识>` 分支，工作目录为 `<协作根目录>/.bot-group-worktrees/<项目 ID>/<成员标识>`。各方向均以办公机项目的 `master` 提交为准备基线。项目成员卡显示远端回报的路径、分支或失败原因，“准备远程工作区”可重试。

话题和点对点聊天使用远程 Hermes 会话自己的目录。即使仓库尚未准备好，在线成员仍可收发消息，管理员可在群里告知仓库地址和基线。执行项目任务时，引擎才将会话切换到已验证的项目目录。领取任务要求工作区已经准备到当前基线。

首次克隆会在协作根目录下使用临时目录 `.relay-clone-*/repo`。Git 对象下载完成且基线核对通过后，插件检出文件并将仓库移到正式项目目录。网络中断时可在恢复后重试；提示“缺少办公机基线”时，应确认指定提交已同步到项目 origin 的 master。

首次准备前，把需要协作的基线同步到双方可访问的 origin/master。已有目录会核对仓库、分支和提交，能够快进时才更新。有本地修改阻止更新、分支已分叉或仓库不匹配时，按卡片提示处理。成员提交后按项目流程推送协作分支，维护者审查并合并。

**配对后验证。** 在节点卡片中检查当前方向和在线状态。需要切换时，打开该卡片的“切换方向”，选择目标方向并确认。在“连接详情”可查看监听、认证和成员名单读取结果。要验证群内派发，先将成员加入目标项目，再在话题点名，核对回复人和回复话题。

常驻网关的连接配置如下。

| 配置项 | 说明 |
| --- | --- |
| `BOT_GROUP_RELAY_FINGERPRINT` | 自签名办公机证书的 SHA-256 指纹（64 位十六进制，由邀请提供） |
| `BOT_GROUP_ENGINE_URL` | 引擎地址（`https://host:port`，不带路径） |
| `BOT_GROUP_RELAY_INVITE` | 首次由云端连本机时使用的一次性邀请，与引擎地址一同配置后即可启动配对 |
| `BOT_GROUP_RELAY_MEMBER` | 引擎节点注册的成员名（通常即 profile 名） |
| `BOT_GROUP_RELAY_CREDENTIAL` | 节点连接凭据（引擎注册时下发，只存本机） |
| `BOT_GROUP_MCP_PYTHON` | 可选：随包 MCP 解释器绝对路径（默认自动探测 `插件目录/venv/bin/python`） |

配置后重启 gateway 生效。插件目录为 `$HERMES_HOME/plugins/bot-group-relay/`，
解包后目录结构（gateway 插件发现要求直接子目录含 `__init__.py`）：

```
bot-group-relay/
├── plugin.yaml  __init__.py  adapter.py  config.py  relay.py
├── streams.py  tickets.py  mcp_digest.py
├── VERSION              # 发布版本标识（打包时注入，插件版本单一事实源）
├── mcp/                 # 随包 MCP（server.py + requirements.txt）
├── engine/              # mcp 运行时最小子集（mcp_http / process_query）
├── requirements.lock    # 随包 MCP 依赖锁
└── install.sh
```

## 4. 通信协议版本

- 归档内 `VERSION` 文件由发布工具打包时注入**实际发布版本**（与主包同 tag），
  插件握手上报的 `plugin_version`/`code_version` 读它（`config.plugin_version()`：
  VERSION 文件 > `BOT_GROUP_RELAY_VERSION` 环境变量 > 源码常量兜底）。
- 每条连接选择双方都支持的最高协议版本。当前实现支持协议 2 和 1，协议 2 支持长响应分片和单流释放。
- 旧引擎接收插件连接、旧插件接收首次配对探测时可能要求软件发布版本相同。跨发布版本配对时，应先升级执行该检查的一端。

## 5. MCP 随包自动注入

- 引擎按节点配置渲染 MCP 启动命令与 env，经 relay 帧下发、插件原样转发到本机
  gateway；用户装一次插件、填一次配置，**不单独配 MCP、不复制成员 token**。
- 插件握手时上报随包 MCP 的**解释器绝对路径、入口绝对路径、版本与内容摘要**
  （摘要 = `mcp/server.py` + `mcp/requirements.txt` + `requirements.lock` 的 sha256
  组合，只覆盖 MCP 包与依赖清单，不含 env 或令牌）。节点已配置预期摘要时，引擎独立核对指纹。
- 升级：正常升级=重启 gateway/插件（WS 断开重来）；「连接不断、磁盘 MCP 包原地
  替换」场景，引擎在 configure 前经 `mcp_snapshot_request` 同步问询，插件实时
  重算摘要回复——系统重核摘要再配会话，缓存不失效。

## 6. 权限与共存

- **chat/work 权限**：由引擎会话执行范围收窄（execution token 绑定 project/member/
  chat-work），插件不参与鉴权，只传令。
- **本地直连共存**：同一台机器上的本机 spawn/网关直连路径与 relay 互不影响；
  引擎按成员是否注册 relay 节点分流（注册走 relay、未注册走本机直连）。
- **多成员同机隔离**：同一 ECS 两个 profile 各配一条出站 WSS（各填自己的
  member/credential），引擎按 member 派发、插件按 home 维护本机连接，
  回复与事件各回各话题。

## 7. 已配对节点切换方向

在节点卡选择「切换方向」并确认。切到「本机连云端」时，当前通道可通知云端插件打开已配对的监听端口，引擎按保存的证书指纹认证后交接。切到「云端连本机」时，请先启用本机监听，并在节点卡允许该云端来源 IP。云端回连认证成功后，引擎释放原通道。端口占用、认证失败或回连超时会保留仍在线的原通道。

网关启动时按该 profile 最近认证的方向恢复。作为监听方时，它使用已配对的绑定地址、端口和证书启动 relay 和本机 MCP 代理。仅通过监听配对的旧安装可使用原网卡 IP、端口及默认的 `state/cert.pem` 和 `state/key.pem` 恢复。旧配对仅保存公布地址；公布地址经过 NAT 映射或证书存放在自定义路径时，需在升级后用原参数执行一次监听配对配置。

## 8. 长历史会话升级

将办公机引擎和每个远程 Hermes 插件更新至同一发布版本。使用源码运行引擎时，先取得对应标签。使用本版的 `install-relay.pyz` 在原 Hermes profile 中升级插件，再重启该 profile 的网关及办公机引擎。沿用已有配对和连接方向。

升级后打开一个有长历史的既有远程会话。页面应能显示对应轮次的思考记录，节点保持在线。历史读取在后台进行，同一会话的读取可以共享。现场核验可将页面展示的消息编号、顺序和内容与 ECS 网关导出的同一轮次记录核对。

## 9. 排障

项目详情的“成员与目录”先显示已加入该项目的远程成员。远程工作会话状态随后在各自的成员卡片中更新；引擎优先读取项目会话绑定，缺少绑定时才通过 relay 只读查询。节点离线或查询超时时，卡片提示状态未知，可点击“刷新状态”重试。

| 现象 | 处置 |
| --- | --- |
| 节点在线，`session.resume` 或 `session.export` 断流 | 按时间对照引擎和插件的 `relay gateway stream closed`，核对 stream 和 WebSocket 关闭码。两个连接方向均支持历史回复分块，每条网关回复最多 64 MiB。关闭码 1009 表示超出接收上限。引擎与云端插件均需包含分块支持。 |
| 节点在线，点名在 `runtime.describe` 超时 | 对照同一时段的办公机日志和 ECS 插件的 stream 日志。插件通过当前 profile 的 `interactive` 票据连接 ECS 本机网关；取票失败时核对插件包与网关版本。 |
| 页面提示成员名已被使用 | 对照已有节点和 ECS 当前 profile。已有节点在原卡片管理；新增独立节点使用另一个 profile 名。 |
| 页面提示证书核验失败或配对过期 | 证书失败时，从目标 profile 重新取得配对链接并核对指纹。过期时重新核验仍有效的链接，或在“云端连本机”重新生成邀请。 |
| 握手被拒 4001 | 凭据错或已吊销：引擎 `POST /relay/nodes/{member}` 重新注册/下发 |
| 握手被拒 4002 | 随包 MCP 摘要与引擎节点配置 `_package_sha` 不符：升级插件包或更新节点配置 |
| 握手被拒 4003 | 查看两端支持的协议版本。旧版接收端可能仍校验发布标签，升级该端后重新连接。 |
| 连接建立但无派发 | 引擎节点 offline（心跳 90s TTL）：查 gateway 日志与出站网络 |
| 首装 MCP 拉起失败 | 检查 `install.sh` 输出与 `venv/bin/python` 是否存在，MCP 日志在 gateway 会话日志 |

## 远程成员配置编辑

引擎与插件协商到协议 3 或更高版本后，管理员可在成员列表点“编辑成员”读取和保存该远程网关的描述、SOUL、模型配置和 `.env`。项目模型覆盖仍存储在当前项目。

更新引擎后重新启动引擎，更新每个目标 profile 的插件后重新启动相应 Hermes 网关。节点离线或协议过旧时编辑器会提示处理方式。成功写入前插件将变更文件的原件备份到远端 profile 的 `.group-engine-backups/`。并发修改后重新打开编辑窗口获取最新值。保存时断线，编辑器会尝试回读；仍待确认时，在节点恢复后重开编辑窗口核对。
