# 角色名称字符校验

角色名称与成员角色文本在写入前统一过滤不可见字符，避免出现视觉相同、编码不同的名称导致成员筛选和任务派单失效。

## 现状与问题

角色名称和成员角色文本有三处写入入口：

| 入口 | 代码位置 | 现有校验 |
| --- | --- | --- |
| 创建角色 | `engine/project_team.py:create_role` | 非空、长度不超过 100、拒绝 `ord(c) < 32` |
| 改名角色 | `engine/api.py:patch_project_role` | 非空、长度不超过 100、拒绝 `ord(c) < 32` |
| 成员角色文本 | `engine/project_team.py:assign_role` | 长度不超过 200、拒绝 `\r`、`\n`、`\0` |

三处均未拒绝 Unicode 格式字符。零宽非连接符（U+200C）、零宽空格（U+200B）、字节序标记（U+FEFF）等字符可写入角色名称与成员角色文本，页面与接口显示为可见文字，实际存储值包含额外码点。

按名称匹配的读取路径以原文比较：`GET /members?project={项目}&active_only=true&role={角色}` 的结果用于 `group_list_members(role=...)` 的队友筛选，并参与任务 `next_bot` 派单与 @ 人。名称含不可见字符时，按可见文字查询返回空列表。

本项目 2026-10-31 出现角色 1857684 的名称尾部含 U+200C，按可见文字 secretary 筛选返回空。该角色已改名，写入校验缺口未修复，同类名称可再次写入。

## 范围

包含：

- `engine/project_team.py` 的角色创建与成员角色文本校验、`engine/api.py` 的角色改名校验统一为同一套字符规则。
- 覆盖三条调用路径：项目配置页的角色与成员操作、创建向导提交（`engine/project_import.py` 的角色与成员配置阶段）、MCP `project_config` 的 roles 与 members 区域。
- 补充角色名称与成员角色文本的回归用例，接入现有测试入口。

不包含：

- 历史数据的一次性清洗。存量名称是否需要扫描和修正由维护者另行确认范围。
- 用户称呼、项目显示名、Bot 显示名等其他文本字段。
- Hermes、Codex 宿主 profile 名称，其规则由宿主维护。

## 方案

在角色名称与成员角色文本写入前统一校验，拒绝以下字符类别：

- 控制字符（Unicode 类别 Cc）。
- 格式字符（Unicode 类别 Cf），包含零宽非连接符、零宽空格与字节序标记。
- 孤立代理项与未分配码点。

中文、字母、数字、空格、连字符等常规可见字符保持允许，长度上限沿用现有 100 与 200。校验规则提取为公共函数，由三处写入点调用；拒绝时沿用现有单行文本提示格式，并说明被拒绝的字符与位置。错误码与提示文案由架构师确认后实现。

## 验收标准

1. 创建角色时名称含零宽非连接符、零宽空格、字节序标记或控制字符被拒绝，错误信息指明被拒绝的字符，角色表不新增记录。
2. 改名角色适用同一规则，被拒绝时原名称保持不变。
3. 成员角色文本适用同一规则，空字符串仍可保存并清空角色关联。
4. 合法名称保存成功，`GET /members?project={项目}&active_only=true&role={名称}` 精确返回对应成员。
5. 项目配置页、创建向导与 `project_config` 工具三条路径行为一致。
6. 既有角色与成员的读取、改名、授权、成员筛选不受影响，回归用例通过。
