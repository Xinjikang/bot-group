# 软件项目文档与报告目录

## 范围

软件模板与引擎自身统一使用 docs。需求、设计、工程知识与指南随 Git 管理，测试及技术调研报告归入主目录 reports 并忽略 Git。其他项目的实际文件由各项目独立迁移。

## 分类

| 路径 | 内容 |
| --- | --- |
| docs/requirements | 需求、范围与验收标准 |
| docs/design | 正式采纳的方案、设计与取舍依据 |
| docs/ui-spec | 项目 UI 规范，入口 UI-SPEC.md；前端维护、审查员核验 |
| docs/engineering | 已实现的架构、接口与维护契约 |
| docs/guides | 使用、安装、发布及协作指南 |
| reports/tests | 测试、审查验证、诊断与现场证据 |
| reports/research | 技术调研、选型对比与可行性实验 |

## 迁移与验收

存量文档按内容分类，以最新有效版本为准，清理过时副本，仍有效的独有内容整理到对应专题。历史原稿按用途归类，任务中的旧路径通过迁移映射定位。

角色、权限、交接、审查返修与验收关闭遵循项目现有流程。上游交接文档路径和提交，下游同步基线；报告由 shared/worktree 成员共用主目录路径。独立版本测试由用户发起。

验证文档链接、初始化文件和 Git 边界、工作区授权、模板快照恢复、任务流程与源码归档。具体约定见 [文档与报告](../guides/DOCUMENT-STORAGE.md)。
