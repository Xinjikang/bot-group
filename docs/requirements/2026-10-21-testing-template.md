# 独立测试项目模板

## 目标与角色
提供测试项目模板，由测试负责人、测试工程师和测试评审员协作。负责人管理需求、任务、范围和报告验收；工程师维护用例及脚本、执行测试和记录缺陷；评审员独立核验覆盖、断言、执行证据和报告。测试工程师可配置多人。

## 产品依据
接收用户提供或指定的 PRD 与产品原型，记录权威来源、版本、确认状态和使用方式。原型支持本地资料或链接。PRD、原型的冲突与缺项交用户确认，受影响用例标记待澄清或受阻。

## 用例、脚本和维护
用例定义验证目标、前置条件、输入、步骤和预期，保存在 docs/cases。脚本默认放在 scripts；已有项目沿用原脚本位置，scripts/TEST_INDEX.md 集中维护用例与脚本的多对多映射、运行命令、依赖及人工部分。

需求和原型变更先分析用例影响，再同步脚本、数据和索引，验证后同批提交。用例保持稳定编号及修订版本，缺陷补齐最小复现用例。每轮结果绑定 PRD、原型、用例、脚本、被测产品和环境版本，历史记录保持可追溯。

## 目录与交付
docs/product 保存产品依据，docs/plan 保存测试计划，docs/cases 保存用例和覆盖，docs/environment 保存环境说明。项目主目录 reports/<测试轮次>/ 保存报告、缺陷、执行记录与证据；报告通过忽略规则排除 Git 并随项目备份。

流程为范围确认、计划及用例设计、评审、执行、证据与报告核验、报告交付验收。产品质量结论与报告交付状态分别记录；产品修复和下一轮测试由用户另行安排。

## SOUL 参考
测试项目提供三份专业角色参考，同时完善产品原型四份与算法研发四份参考的专业方法、判断标准、沟通和交付习惯。参考可跨项目复用，采用由用户决定，宿主人格文件保持用户配置。

## 验收
覆盖模板列表、创建导入、角色改名、默认授权、用例脚本映射、报告闭环、shared/worktree、既有资料保护、旧 doc 目录复用、历史选择恢复、模板资源打包及 Chrome 创建刷新。实现说明见[测试项目模板](../engineering/TESTING-TEMPLATE.md)。
