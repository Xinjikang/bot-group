# 项目脚手架与协作模板需求

## 目标

创建项目时可选择空白项目或内置模板，获得可用的项目约定、文档入口、角色分工、授权与场景文件。已登记项目直接打开，导入已有目录和新建项目分别提供向导。

当前支持软件开发、产品调研、内容写作和产品原型设计，模板文件清单以各自 manifest 为准。空白项目生成 AGENTS.md、README.md 和 docs/INDEX.md，成员与 Bot 授权初始为空。

## 身份、角色与配置

宿主 Profile 提供运行配置，Bot 提供稳定身份，项目成员保存角色、权限、启停、工作区与会话关系。单成员关联一个角色，同角色可有多名成员，角色改名保持稳定 ID 及授权关联。

模板沿用选定 Bot 的宿主、模型和配置，SOUL 仅作展示、复制与下载参考。应用模板配置项目文件、成员、角色、负责人和权限。成员目录授权通过项目入组和工作区配置执行。

## 文件与模板

新项目统一使用 docs，既有 doc 项目按导入兼容规则处理。软件模板将需求、设计、工程和指南分类，报告单独保存；其他模板依据各自成果形式组织目录。

静态模板 manifest 记录 ID、版本、角色、权限、资源、参考和目录模式。变量按白名单作一次文本替换，模板中的脚本按普通文件生成。资源和目标路径都需校验，生成前检查权限名称、角色完整性及成员有效性。

生成后的项目规则由项目维护，参考快照记录创建时版本。更新模板保持既有初始化快照的恢复能力。文件冲突默认保留；明确选择替换规则时先备份。

## 向导与初始化

1. 填写项目名称、简介、目录及模板。
2. 查看角色与流程，分配 Bot、负责人和权限。
3. 预览文件、冲突、成员及权限变更。
4. 确认后提交暂存计划，显示阶段及逐项结果。

项目登记保持其原有契约，文件初始化由独立服务编排。初始化使用稳定 ID、内容指纹、明确阶段和幂等重试；配置事务与文件发布分别核验。初始化期间通过就绪门禁阻止调度，失败保留阶段及原因，重试检测用户改动并保护已有文件。

shared 模式按项目约定串行协作，worktree 模式要求 Git 基线、目录归属、任务分支和交接提交明确。清理由显式操作处理，并核对运行资源与用户改动。

## 验收

覆盖空白项目、四类模板、两种目录模式、角色改名、同角色多成员、授权、目录保护、重复提交、中断恢复、就绪门禁、SOUL 参考及宿主配置保护。验证文件清单与预览一致，链接可解析，各模板任务流程能交付和关闭。

自动化验证采用隔离 SQLite/Git/宿主目录；真实模型调用另行记录授权和成本，执行结果保存在测试报告。
