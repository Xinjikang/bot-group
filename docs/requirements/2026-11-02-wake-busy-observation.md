# 修复 Hermes 原生忙闲漏判导致的跨会话调度阻塞，并补齐自发执行状态展示

需求编号：#142。依据话题 10126 已确认的方案汇总（2026-11-02）立项，授权来源见需求任务池记录。

## 现状与问题

Hermes 收到异步子任务完成回调后，可在其原生会话中自动续跑。此轮执行没有引擎执行表记录，导致两类问题：

1. **调度饥饿**：队列预检查 `session_busy` 经 `find_bot_processes` 调用 `hermes_gateway.process_state`，依据 `hermes_executions`/`wake_runs` 引擎记录判空闲或交回进程查询，看不到网关原生 running/pending。投递阶段经绑定 attach 原生会话才发现忙，任务退回 `queued` 保留原 ID；下一轮按 ID 排序又选中同一项，反复循环占住队首，后方独立话题、工作会话（含共用队列的 Codex、DSH 任务）全部饥饿。
2. **状态展示缺失**：`GET /thinking` 按心跳 pid 关联 `wake_runs` 补会话身份，自发续跑无引擎记录，思考条无法挂载，执行结束也无撤下事件。

现场实例（2026-11-02）：17:39:43 子任务完成回调驱动自发续跑；17:39:51 新唤醒入队首，busy 循环；17:49:00 执行结束、17:49:04 恢复投递，全局阻塞约 557 秒。隔离复现：`process_one` 连续 20 轮全部选中忙碌会话、空闲会话 0 次投递，解除 busy 后两项立即完成。证据：`reports/research/2026-11-02-wake-stall/evidence.json`。

## 范围

包含：

1. 补齐 Hermes 网关托管会话的原生 running/pending 忙闲预检查，含查询异常、超时、性能与缓存失效处理。
2. 补齐 `/thinking` 对 Hermes 自发执行的活动状态、归属与结束状态展示，按实际需要配合前端。
3. 回归与验收：现有 20 轮复现整理为 `scripts/` 可重复回归并同步测试索引；Hermes/Codex/DSH 混合调度回归；隔离真机验收。

保留：

- `queue.py` 按会话跳过 busy 的调度规则、第 143 行退回逻辑、任务原 ID 与原顺序。
- 同话题按发言轮次、同工作会话按请求顺序；独立话题、独立工作会话继续调度。
- CLI/Codex/DSH 现有运行时查询语义。

范围外：busy 任务移队尾或新增延迟重排策略；修改 Hermes 源码；无关运行时重构；生产数据实验；自动生产重启。

## 方案

见设计文档 [`docs/design/2026-11-02-wake-busy-observation.md`](../design/2026-11-02-wake-busy-observation.md)。要点：

- 按 runtime 与会话绑定接入 Hermes 原生状态；内存已知占用快速判忙，引擎执行记录与原生 running/pending 任一表明占用均按忙碌处理。
- 原生查询失败或未知时暂缓目标会话，其他独立会话继续获得调度机会；查询设超时与明确性能边界。
- 采用短 TTL 缓存时，按原生会话与绑定代次隔离，`/new` 或绑定切换失效，覆盖缓存空闲期间新执行启动的竞态。
- `/thinking` 以原生执行观察补充引擎记录，观察记录与引擎主动派发记录分开，仅在有证据时关联任务与消息。

## 验收标准

1. 现有 20 轮通用队列饥饿复现整理为 `scripts/` 可重复回归（实际 `process_one` + 隔离数据库）：A 会话原生 busy 且引擎表缺记录时，B 空闲会话获得投递；A 保留原 ID 等待，解除 busy 后恢复。
2. 验证同工作会话请求原序、同话题发言轮次；不同话题、不同 Bot、同 Bot 的独立 work/chat 会话继续推进。
3. 预检查后才变忙、缓存空闲期间原生执行启动两种竞态：投递返回 busy 后按原逻辑退回，其他就绪会话继续获得调度机会。
4. 原生查询超时、断连及未知状态只暂缓对应会话，其他独立会话继续推进，查询恢复后恢复调度；验证查询耗时与频率边界，采用缓存时验证绑定切换失效。
5. `/thinking` 显示自发执行的正确成员、项目、work/话题归属，执行结束后撤下对应活动状态。
6. 新增明确标注 Hermes/Codex/DSH 的混合调度回归：Hermes 原生忙时后方 Codex、DSH 就绪任务获得投递；Codex、DSH 各自验证忙时跳过、空闲恢复与同会话保序；运行相关既有队列用例。
7. 单列隔离真机验收：真实异步子任务完成回调驱动 Hermes 自发续跑，关联原生会话/回执、引擎记录、调度及 `/thinking` 证据，证明真实触发时其他独立会话继续推进。模拟层与真实运行层分别记录，明确三 runtime 各自验证层级及未覆盖项。
8. 新增/修改/执行测试前阅读 `scripts/TEST_INDEX.md`，可复用脚本同步索引并参数化外部资源；使用引擎分配的隔离端口、监听地址与数据目录，核验运行资源并清理临时进程。报告写入项目主目录 `reports/tests/<版本>/<日期>-<任务ID>/`，写前用 `git check-ignore` 核验；任务节点记录报告绝对路径、被测提交、结果与遗留项；相关代码与文档提交、代码索引更新，按项目流程完成审查与验收。
