# 需求恢复调度与投递有效性

## 范围与验收

需求处于待拆或拆解占用超时状态时，扫描入队、唤醒上下文及队列投递使用相同的恢复条件。关联任务存在阻塞时暂停自动拆解恢复；任务恢复后重新参与扫描。真实未读消息和可执行任务保持独立调度。

验收覆盖阻塞需求连续扫描、阻塞解除、部分拆解续作、未过期占用、完成与归档、来源失效、权限及成员变化、项目未就绪、负责人配置协调、队列失效取消，以及合并消息和任务保留。

## 查询与上下文

`engine/requirement_recovery.py` 提供共享查询与拆解成员选择。查询要求项目就绪且有效、需求 open 且未归档、拆解 pending 或租约过期、关联任务均未处于 blocked。需求字段和来源继续经过 `requirement_gate.check`。扫描保存门禁原因，提示构造和投递校验保持只读。

扫描按项目角色与 profile 的稳定顺序选择一名有效 task.create 成员。任何当前已授权成员在已有 work 唤醒中均可取得有效需求上下文。缺少有效拆解成员时，仅当前启用的项目负责人取得配置协调指令；指令要求联系管理员配置授权。

已有任务的需求继续恢复拆解。提示携带需求 ID，要求读取并复用已有任务，补齐说明与依赖，按拆解凭据契约续写并显式提交 complete=true。活跃占用和已完成拆解保持现有状态。空收件箱的任务或需求执行明确说明调度原因。

## 队列与并发边界

`scan:req` 在队列领取后、投递前重新读取需求上下文、未读消息及可执行任务。三项均为空时标记 cancelled 并记录原因。消息或任务合并进同一 work 队列项时保留投递。模型启动前的提示继续使用实时快照，任务工具的既有事务门禁负责启动后发生的业务状态变化。

周期仍为 180 秒，queued/running 去重规则保持现有契约。该变更无需数据库迁移或生产数据修补。

## 验证边界

回归使用独立 SQLite、真实队列函数及模型启动替身，覆盖连续扫描与领取期间状态变化。生产部署后的运行观察单独记录；引擎更新由管理员手动重启。
