# Hermes MCP 初始化失败恢复

## 范围与约束

修改范围为 bot-group 的网关适配、诊断和队列恢复。Hermes 源码及配置保持原值，适配器使用现有公开 RPC。Hermes 内部连接期限继续遵循宿主契约。

## 行为

网关终态回执的 `result.error` 经现有凭据脱敏后保存，通知分类识别 MCP 初始化失败。接入日志记录连接、绑定、配置和提交阶段的状态、耗时及错误类型。

自动恢复要求同一 admission 的权威 failed 回执同时包含：`failed=true`、`completed=false`、空 messages、空 final_response，以及精确的 `RuntimeStoreError: acp_mcp_discovery_failed`。仅该组合确认执行在模型和工具运行前失败。每个原 wake job 最多恢复一次，计数来自持久执行账本，重启保留预算。

恢复沿用原 wake job ID、触发消息和队列位置。原队列继续检查项目、成员、话题轮次与排序冲突。成员停用、话题变化、主动停止、停机、已有冲突作业、结果不明及已发生业务执行均关闭恢复。恢复前通过 `session.mutate editor_mcp` 重新连接任务工具，并检查公开回执中的 `mcp_servers`；缺少 task_queue 时在提交业务消息前结束。

首次可恢复失败完成原执行清理后重新排队，保留话题发言位。恢复成功沿用正常结果；预算耗尽时写入明确的初始化失败通知，并保留脱敏原始诊断。原始 admission/submission 保持独立，未知结果只查询原回执。

## 验证

隔离数据库和模拟 RPC 覆盖：错误保存与脱敏、终态诊断补读、身份/代次校验、一次恢复及耗尽、原作业顺序、话题变化、停止与停机保护、工具重连失败前零业务提交、已有执行与结果未知的零重提。接入阶段日志验证耗时字段及凭据隔离。运行相关网关、队列和异常分类回归，报告写入项目主目录的忽略目录。

部署后由管理员手动重启 bot-group 引擎；Hermes 网关保持原实现。
