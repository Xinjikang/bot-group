# 远程 Hermes 通信协议版本

适用于插件主动连接引擎和引擎主动连接插件两个方向。协议定义位于 `engine/relay_protocol.py`，发布工具将同一文件装入插件包。

旧引擎在接受邀请及已配对插件连入时检查发布版本，旧插件在引擎探测配对链接时也检查发布版本。v0.3.3 和 v0.3.4 都声明协议 1，v0.3.4 新增了通过 `accept_chunks` 声明接收分片的能力。

协议 2 的握手携带 `protocol_versions: [2, 1]`，另保留旧端能读取的 `protocol_version: 1`。接收端在回执的 `relay.protocol_version` 中返回最高共同版本。旧端缺省回执对应协议 1。引擎在协议 2 上请求分片和流释放。只支持旧握手的历史引擎在单条流中显式请求分片时，插件沿用该请求的响应格式。

## 兼容规则

- 每条连接独立协商双方都支持的协议版本。在邀请、配对探测和日常重连中使用同一兼容规则。产品发布版本继续用于节点展示、诊断和升级提示。
- 每次修改线上通信契约都提升协议版本，包括新增可选字段或帧、修改字段含义、调整握手、身份确认或消息收发顺序。协议契约保持原样时沿用原协议版本，包括只修改界面、优化数据库、修复实现以符合既有协议或单独发布产品的情形。
- 协议升版与继续支持旧版分别管理。新端可以实现多个已定义的版本，建立连接后按选定版本的字段、帧和交互规则收发。同一版本中已定义为可选的能力，由双方按该版规则启用。双方没有共同协议时，在配对或建立连接阶段提示两端支持的版本。身份验证、来源绑定和已配置的 MCP 指纹校验继续独立执行。
- 仅发送单个协议号的旧端按其声明的单一版本处理。旧发行包可能自行拒绝不同发布版本的对端，升级说明应标明哪个端点需要更新。历史版本的兼容范围用真实跨版本握手、会话收发和大历史响应验证。

## 日常连接与重试

引擎与网关插件从同一份 `engine/relay_retry.py` 读取固定退避序列。每条配对连接独立维护一轮拨号；认证成功后归零。断网、连接超时和认证回执超时允许重试。4001 至 4004 分别表示凭据、MCP、协议和来源被拒绝。4005 要求重新读取当前方向与切换意图；已选监听的一端恢复监听，方向仍冲突时暂停。首次配对的待确认回执按配对流程处理。

引擎将停拨原因持久化到节点，插件将停拨状态与汇总写入对应引擎的本地配对记录。正常启动恢复已选方向，已停拨节点保持暂停。引擎节点页的重试请求与云端私聊工具分别唤起本地拨号器。云端工具仅选择已有配对，多引擎时按保存的地址选择。连接时序、等待时间和操作入口见[安装指南](../guides/BOT-GROUP-RELAY-INSTALL.md#离线后的重连)。

## 验收

在“本机连云端”重连期间，插件可能已接受认证，而引擎还在登记连接。此时请求切回“云端连本机”，引擎保留已认证的拨号路径并通过它通知同一个插件回连。以目标连接的认证结果完成切换，交接超时后恢复原方向。

使用不同发布版本的引擎和插件验证两个拨号方向的首次接入、重连与回复。同一 profile 同时连接两台引擎时，每条连接使用自己协商的协议和能力。一个引擎不能接收分片或没有共同协议时，另一条连接继续按自身能力工作。
