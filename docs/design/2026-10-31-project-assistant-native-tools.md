# 项目助手复用宿主原生执行能力

## 职责与工具

项目助手使用用户选定的 Hermes 或 Codex agent，在独立助手会话中完成资料查找、文档编写和结果检查。bot-group 提供项目上下文、工作目录、配置业务接口与 HUD。Hermes 选用原生 file 和 memory 工具集，宿主按所选 profile 配置加载记忆及记忆提供方工具。Codex 保留原生命令执行、补丁编辑与原生记忆能力。宿主模型、提供方和身份来源沿用所选配置，工具选择覆盖仅作用于助手会话。

额外提供两个业务入口：`project_config` 读取并修改当前项目数据库配置、复用已有 profile 创建接口；`open_project_page` 请求 HUD 打开当前项目配置窗口的指定标签。数据库操作覆盖基础配置、角色管理、成员启停、角色分配与角色权限，角色权限修改保留其他授权。工具绑定当前助手会话及项目，复用现有业务校验、版本检查、项目状态与审计；写入只在当前有效且有用户请求的执行中生效。

操作步骤放在助手系统提示词中。助手按需读配置与版本、选择目标角色和操作、调用业务工具并检查返回结果。创建指定角色的新 profile 时，助手读取当前模板对应角色的 SOUL 全文，以此初始化 profile，再分配项目角色并核对创建结果中的文件校验，在宿主已授权范围内可原生回读。AGENTS.md 与 SOUL 的读取和编辑使用宿主原生文件工具，业务工具仅接收 profile 创建所需的初始说明。

文档内容由宿主文件工具直接修改，工具执行结果和实际文件作为完成依据。HUD 显示文件路径、修改摘要及待确认事项；文档全文保存在项目中。既有确认提案保留兼容处理，新增文档任务使用原生工具。

原生工具开始与完成事件用于显示当前读取、写入、配置和导航阶段。不可见角色字符以可见转义值、字符序号和 Unicode 码点提供证据；名称精确筛选与基于成员 profile、role_id 的授权分别核对。

## 检查与上下文

创建完成和用户主动要求时立即检查。后台兜底间隔为一小时，周期内直接跳过项目资料扫描；周期到达后先比较文件元数据与配置，存在变化时排队。页面状态轮询只读取会话状态。项目正文通过原生工具按需阅读，模板规则、资料入口和使用文档来源注入上下文。

## 验收

单元验证覆盖受限 MCP 清单、会话/项目/执行权限、草稿和详情配置更新、版本冲突、宿主启动参数与低频扫描。实际验收使用用户配置的模型与 agent，在隔离项目中读取输入资料、生成及修改文档、调用配置工具更新配置，并核对文件正文、保留内容、来源与数据库实际值。记录模型路由、宿主配置指纹、产物、工具调用和 HUD 结果。模拟返回仅用于回归，交付验收以真实 agent 的实际产物为准。

## 原生记忆与历史备注

记忆的存储、检索和整理由所选宿主管理，操作方法放入助手系统提示词。Hermes 沿用 profile 的记忆启用状态、容量和写入审批；项目专属约定标明项目稳定 ID 及适用范围。群聊成员与助手共用 native_runtime 中的 Codex 启动、认证同步、环境清理和 Hermes CLI 入口；Hermes 网关继续共用连接及会话接口。助手使用真实 profile，直接继承模型、认证、权限、原生工具和记忆配置。Codex 使用持久会话，features.memories、memories.generate_memories 和 use_memories 依所选配置生效；Hermes CLI 使用同一 profile 和原有 managed overlay，新增配置只覆盖助手业务 MCP。自动提取、整理和召回遵循 Codex 自身的触发周期与可用能力，显式记忆操作依据实际工具结果汇报。

历史项目备注保留在 HUD 历史数据与旧提案兼容处理中，既有 settings.maintenance_facts 原值保留。引擎停止更新及注入这项历史资料。成员唤醒继续注入项目稳定 ID、名称、描述、负责人、主目录、工作目录和工作区配置；角色与协作规则沿用原有加载流程。助手的类型要求、模板、资料元数据、配置快照与对话上下文保持现有契约。
