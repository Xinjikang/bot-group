# 常驻执行后端方案

状态：待实施方案。当前运行契约见 [工程约定](../engineering/ENGINEERING.md)。本页保留选定方案的设计边界与验收条件，实施状态以代码和任务记录为准。

## 目标与分层

通过复用服务进程和会话中的 agent，减少每轮启动与构建成本。进程数量、agent 数量、历史长度和工具子进程分别计量。

公共层负责消息批次、会话绑定、话题调度、回复解析、need_reply、已读确认及任务授权；运行层定义提交、收输出与状态、停止确认、steer、恢复和能力查询。

传输后端分为 SubprocessBackend 与 ServeBackend。子进程后端内部按 Hermes/Codex 分别拼接命令和解析输出，共享进程生命周期；serve 使用 Hermes 原生 WS/JSON-RPC。UI 按适用 runtime 和实际能力展示选项，切换前检查在途执行并确认结束。

## 会话与消息

- work 按成员和项目固定会话，chat 进一步按话题绑定；一个会话绑定一个项目和工作区。
- 每轮记录注入的消息 ID，超预算消息等待后续发言位。成功回复或合法跳过后确认处理，失败和中断保留待处理状态。
- 最终回复由引擎绑定目标并投递，输出解析必须区分最终正文、推理和日志。
- 话题结果包括 reply、silent_skip、public_skip。reply 包含正文和 need_reply；silent_skip 记录跳过并释放发言位；public_skip 落消息但免分发，避免互相唤醒。
- 空输出按失败或中断核查。工作群输出采用 reply，任务进度和完成仍由任务工具推进。
- 静态协作规则保持稳定，动态身份、任务和消息按本轮传入。重要结论落到文档与任务节点，避免仅依赖会话历史。

## 停止、恢复与缓存

serve 方案区分三个动作：`session.interrupt` 停当前 turn；`session.close` 关闭会话并释放 agent；停止服务进程树回收整个后端。中断回执需核验工具收尾，软中断和进程退出分别记录。

`session.steer` 的账本受理、通道接受、执行收到分别记录。后端能力不足时明确标示。跨后端恢复须验证原生会话历史及逻辑绑定。

2026-10 的调研区分了三种缓存实现：

| 形态 | 当时核查的复用方式 |
| --- | --- |
| serve / tui_gateway | session 持有 agent，支持空闲回收与容量限制 |
| 消息平台 GatewayRunner | 独立的 agent cache 与回收机制 |
| API server Runs | 每次 run 构建并清理 agent |

方案默认长连接维持复用。WS 断开后的 detached 状态与空闲回收条件相关；连接形态、历史持久化和 agent 对象复用分别验证。短 TTL 自动回收、活跃保护、大量长历史会话和真实模型峰值仍需专项验证。宿主升级时重新核对接口与配置语义。

## 身份与权限

共享服务中的身份需要逐执行传递和校验。project 参数之外，还要核验成员、kind、话题、执行代次和凭据有效期。

| 操作类别 | 核验范围 |
| --- | --- |
| 发消息、读收件箱、心跳 | 项目、话题、执行归属及有效期 |
| 创建话题、列成员 | 成员资格与项目范围 |
| 创建需求、拆解任务 | 项目权限、拆解授权及执行绑定 |
| 领取、日志、完成、阻塞 | work 模式、任务授权及当前状态 |
| 显式 task/thread 参数操作 | 目标归属与权限，避免参数跨域 |

当前工具授权以 [访问控制](../engineering/ACCESS-CONTROL.md) 和 API 实现为准。早期按工具名区分“读/写”的清单已由实际权限契约替代。

## 实施与验收

1. 定义后端接口，保留子进程行为基线，分别实现输出收集策略。
2. 接入服务会话绑定、消息批次和结构化回复，验证重复事件、重试及超预算续处理。
3. 接入停止与 steer 回执，验证单 turn 结束、工具子进程收尾和会话恢复。
4. 验证跨项目、跨话题、跨成员、撤权和旧执行凭据；验证两种后端切换时的历史连续性。
5. 测量完整进程树、首次构建、后续 agent、历史增长及闲置回收，记录模型和输入条件。
6. 通过隔离验证后再进入项目部署流程，外部 Hermes 源码维持只读。
