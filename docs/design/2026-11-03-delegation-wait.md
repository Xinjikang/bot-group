# 原生子代理等待与执行续接

## 范围与状态

Hermes ACP 的一次引擎执行可以包含多个原生 admission。主轮 terminal/completed 后，结构化 delegate_task 工具回执中的后台委派 ID 建立持久等待；引擎执行保持归属，状态为 waiting_delegation。最终输出文本保持原有含义。

等待期间结束主轮的活跃显示，保留逻辑执行的 wake_started_at、任务归属、会话凭据及话题发言位。原生回调进入后，同一逻辑执行接续处理该 admission；每个 admission 的身份、代次和终态记录到 hermes_native_turns。

多个独立交付单元分别保存 ID；工具返回的 units 是独立单元的权威集合。子代理列表为空和主会话 idle 都不能结束等待。每个单元的回调 admission 取得终态回执后才记为已消费；回调再次派生子代理时增加新的等待项。

## 恢复与边界

后台协调线程使用记录中的 Hermes profile home，只读打开 state.db，以 target_session_id 和结构化 async_delegation request_id 定位遗漏回调。只查询 session_admissions 的 admission_id、request_id、状态及代次；数据库连接设 query_only，锁等待 250ms，语句预算 500ms。此读取仅用于发现身份，终态始终由公开 prompt.receipt 确认。数据库缺失、版本字段变化或读取失败进入现有未知状态和有界恢复流程，保留执行归属。

该恢复路径覆盖事件流换代、连接丢失及回调在引擎停机期间结束。网关把失去 owner 的委派恢复为 unknown 后，其恢复通知仍按相同委派 ID 进入父会话。协调线程观察并接管原生回调。

每次业务写入在事务内核对绑定代次、成员权限、任务当前归属或话题当前发言位。会话凭据在等待中可服务合法续跑；心跳的可选执行查询返回空闲。任务移交、话题表态推进、成员移除、会话换代、显式停止会终止旧执行的写入资格。

## 点对点与并行调度

工作会话等待期间，实际存在的定向未读消息可加入该逻辑执行的持久输入箱。输入 request_id 在发送前保存，重试复用该 ID；选择候选时跳过已入箱消息，使旧未读记录后的新消息保持可投递。入箱事务同时复核消息仍未读、有效且属于当前接收方。队列中的任务扫描信号本身继续等待，定向消息可以利用同一队列项投递，避免队列唯一索引阻挡后来的点对点消息。新的任务领取仍受当前任务归属和 task_claim 约束。

等待只占用对应会话。保留 #276 的忙会话跳过及后方可用会话投递：不同话题、不同成员的工作会话，以及同一成员的 work/chat 会话继续独立调度。页面状态查询保持本地读路径。

## 验证

用例覆盖正常等待无失败重试、话题保留、结果投递空档、单元独立完成、回调继续派生、引擎重建与原生账本恢复、写入归属变更、停止撤权、点对点投递去重和跨会话调度。原生验收使用隔离网关、本地受控模型、独立引擎数据库与消息 HTTP 接口；现有 #276 调度、会话鉴权、停止及本地状态查询回归一并执行。

验收基线为未修改的 Hermes，脚本记录源码提交、工作区状态及 model_tools.py 摘要并在结束时复核。默认采用 Hermes ACP 工具集，`--toolsets` 可指定对照配置。原生委派、点对点投递与自动回调使用实际网关；`--mcp-path client` 在回调执行期间通过独立真实 stdio MCP 客户端核验 bot-group 写入权限；默认 `native` 由父 agent 调用工具。分别记录两种写入路径的结果。

Hermes `0431192d69d4afd2443a7da15bb9e129a424414c` 在仅启用 `delegation` 的裁剪夹具中复现父轮 editor MCP schema 缺失，工具搜索入口同时缺失。默认 ACP 工具集的原生父轮通过 `tool_search` / `tool_call` 发现并调用会话工具，已验证消息写入、任务交接及话题发言位推进。验收记录工具集及实际调用路径；裁剪夹具的缓存缺陷保留为该配置下的兼容性限制。涉及原生运行时代码注入的实验结果仅保留为调查证据，验收脚本保持原生运行时原样。
