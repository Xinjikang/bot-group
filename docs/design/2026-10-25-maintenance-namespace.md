# 维护代码命名空间

Hermes SessionDB 在引擎解释器内使用宿主的顶层 `tools` 包。维护代码迁到同名顶层包后，两者共享 `sys.modules['tools']`；先加载的包决定后续导入解析，导致会话模块或发布模块导入失败。

维护实现统一放入 `engine.maintenance`。该命名空间属于本项目已有的 engine 包，维护入口仍放在 `tools/`。此划分保留管理员现有命令，同时让宿主包身份在解释器存续期间保持稳定。

公开安装器需要在源码下载之前执行，因此标准库 bootstrap 实现保持单文件独立能力。发布工具从维护实现导出该文件为独立资产；本地 `tools/bootstrap.py` 作为已有命令入口调用同一实现。

验收需覆盖同进程的两种导入顺序、真实 SessionDB 创建和恢复、旧布局升级与失败回滚、源码资产清单及独立安装器。运行与测试契约见 [维护模块](../engineering/MAINTENANCE-MODULES.md)。
