# Hermes 成员模型继承与原生会话策略

## 问题

统一成员编辑器按“项目非空覆盖 → 当前宿主配置”展示模型、供应商与推理强度。项目模型接口的读取保持只读，显式保存时才创建 `member_model:<bot_id>`。覆盖记录缺省属于合法的继承状态。

原唤醒路径只在已保存的项目设置中补齐空模型。覆盖记录缺省时生成空参数，Hermes resume 继续使用原生会话保存的历史模型与策略；界面配置目标和实际调用因此可能不同。已保存的部分覆盖同样会把供应商、推理强度留给历史会话。

## 有效参数

`project_models.arguments()` 对已登记 Hermes 成员逐字段合并项目覆盖和当前物理 profile 的 `config.yaml`。根 profile 使用根配置；命名 profile 使用其 `profiles/<name>/config.yaml`，遵循成员配置编辑器的物理归属。

项目非空值优先。模型支持现有字符串、default/model/name 别名和嵌套模型映射；供应商读取模型配置的 provider，推理强度读取 agent.reasoning_effort，YAML false 转为 none。有效字段通过 --model、--provider、--reasoning 显式传递。有效模型为空时在投递前报错，管理员补齐项目模型或宿主默认值。

参数解析保持配置文件和 settings 表只读，覆盖记录缺省时继续保留缺省状态。全局修改、清空项目覆盖与新保存的字段覆盖在下一次唤醒重新解析。Codex 与 DSH 沿用各自已有参数或 overlay 契约。

## 会话策略

网关沿用 configure/configure_tracked，通过官方 session.mutate 更新变更的模型和推理策略，再按原会话继续执行。绑定、会话 ID、历史和执行归属保持原样；原生策略更新是否回收常驻 agent 由 Hermes 负责。正在运行的轮次沿用其已应用策略，代码更新后由管理员手动重启引擎并刷新页面。

重复文本在原生消息记录中存在时，应继续对照提供商响应、原生累加与持久化链路。模型继承修复验证配置路由一致性；复读发生机制按独立证据分析。

## 验证

项目模型回归覆盖覆盖记录缺省、三个继承字段、字段级覆盖、全局修改、清空覆盖、false→none、命名 profile 与缺失默认值。模拟网关验证旧模型被配置目标替换时保留原 session ID，并核对模型和推理 mutation 的实际载荷。配置字节和 settings 表在参数解析后保持原样。

原生会话复用、已生效策略缓存、配置备份和其他运行时参数复用相邻回归。运行命令与隔离要求见 [测试索引](../../scripts/TEST_INDEX.md)。现场只读参数比对验证配置解析，真实模型调用与运行中会话切换由对应运行环境验收。
