# 项目助手的配置、资料准备与使用问答

## 需求与验收

项目助手承接不同项目类型的配置和资料差异。新建向导与项目详情使用同一套字段知识，结合模板职责、当前配置和已有资料协助用户填写。创建后检查模板要求的文件、文件内待填写内容和项目特有约定。测试项目收集产品需求及原型的权威来源，整理为模板规定的 `docs/product/PRD.md` 与 `docs/product/PROTOTYPE.md`，保留来源、版本和待澄清项。使用问答依据当前安装版本的文档和页面入口。

验收覆盖六类模板及空项目、已有文档与默认骨架的区别、部分读取和路径保护、确认前预览与确认后落盘、并发修改冲突、向导字段填写与详情配置修改、使用资料与项目资料的来源区分。实际模型表达质量与无外部调用的契约测试分别记录。

## 实现

在各模板目录维护助手准备说明，声明输入、配置注意事项及当前阶段需要的资料。模板 manifest 的文件清单提供默认结构依据；准备说明只声明启动所需文档，阶段产物按流程后续完善。通用字段知识、模板说明及当前安装的使用文档组合进每轮上下文。文件检查提供路径、状态、待填位置和来源；截断、不可读与越界均保留未知状态。个性化结构和项目既有约定由模型结合实际资料判断。

模型保持零工具。配置及 Markdown 整理通过提案预览确认；服务端验证字段、项目范围、文件数量与大小、读取时摘要以及确认时现状。目录配置复用现有工作区校验与 Codex 目录授权同步。文件提案记录当前项目根目录及原文件摘要，确认时校验并写入，失败回滚本次文件变更。原始资料只作为内容依据，配置和文件变更由受控执行层完成。

后台检查复用已启用助手的扫描周期，创建会话已选择 AI 时在绑定成功回执后自动排队检查；尚未选择 AI 的草稿保留暂停状态，已有项目继续单独启用。绑定重试保持现有待办。模板默认文件中的说明和占位内容需要确认或补齐，文件存在本身只证明路径可用。使用知识从程序目录读取，与被管理项目中的声明分别标注。
