# 会话恢复与调度故障

## 故障边界

Hermes 的旧本地会话可能保存 `agent:main:local:dm:<id>` 路由。多 profile 网关恢复该成员时使用 `agent:<profile>:local:dm:<id>`，旧记录不一致会返回 `storage_unavailable`。此时工作任务保持 pending，工作唤醒保持 queued；独立话题会话仍可运行。

## 调度诊断

原生预检查将正常忙碌与查询失败分别缓存为 `busy` 和 `error`，二者均暂缓目标会话。查询失败采用 3、6、12、24、30 秒上限退避，保存协议错误码或异常类型；异常正文和 RPC 输入不进入公开诊断。

排队 job 的 `detail` 使用 `session_state_query: ` 前缀，记录状态、原因及绑定身份。连续至少三次查询失败且跨越 60 秒时，通过 `execution_errors` 生成一次引擎告警。去重身份由 job、原生会话和绑定代次组成，进程重启后仍有效。告警不唤醒 Bot、不领取或终结任务、不消耗排队 job。查询恢复或绑定代次切换后清理旧诊断，原 job 按既有调度继续投递。

## 原生兼容边界

Hermes 的兼容处理应校验 receipt 的 home、principal、逻辑身份、物理 lineage、旧路由及各持久化副本一致性。只有完整的旧默认命名空间记录才可迁移；外部 profile、部分损坏、目标路由冲突和活动执行继续拒绝。持久化修改由原生 authority 的受跟踪后台写任务完成，避免阻塞网关事件循环。

迁移保留逻辑会话 ID、消息历史和模型策略，在同一受 epoch 保护的事务中更新 receipt、路由索引及对应 session 行。bot-group 通过既有官方 RPC 使用修复后的宿主。

## 人工恢复

管理员明确授权后，可备份引擎与宿主数据，核验目标工作会话的引擎执行、原生 admission/worker、turn lease 和遗留 CLI 均已空闲，再使用现有会话切换事务建立新的工作会话。保留旧历史、操作记录及新旧绑定代次，之后由正常调度领取任务并交接。现场恢复不自动推广为 `/new` 的放行策略。

## 验证

使用测试索引中的隔离调度组合验证跨会话推进、持续失败去重、进程缓存重建、绑定代次切换和原 job 恢复。原生兼容用例在独立 Hermes home 中执行，覆盖冷恢复、归属保护、路由副本一致性及重复恢复。
