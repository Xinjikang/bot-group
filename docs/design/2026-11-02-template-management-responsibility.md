# 模板管理支持职责与重复返修话题触发提示词

## 背景与目标

协作中反复出现执行成员被打回、管理者支持不足、审查口径与帮助效果缺少持续跟踪的问题。模板已有任务定义、审查交付和协作升级规则，本轮新增具体管理支持行为，并消除与既有规则的重复表述。用户逐项审阅后于消息 10230 要求第一项收口并创建需求（thread 10123）。

## 变更范围

### 1. 角色职责增量（manifest）

路径 `templates/projects/<模板>/manifest.json`，只追加对应 `roles[id].responsibilities` 的新增职责，保留原文与 `permissions`：

- software：owner 追加「统筹整体效率，跟踪协助措施是否解除执行阻塞」；architect 追加「为执行成员提供具体、可验证的技术支持」；reviewer 追加「提供可执行的返修指导」。
- writing：editor 追加「统筹整体效率，提供实质支持并跟踪障碍解除结果」；proofreader 追加「提供可执行的修订指导」。
- algorithm：lead 追加负责人职责；reviewer 追加「提供可执行的返修指导」。
- testing：lead 追加负责人职责；reviewer 追加「提供可执行的修订指导」。
- research：lead 追加负责人职责；verifier 追加「提供可执行的补证与修订指导」。
- product-prototype：pm 追加负责人职责；reviewer 追加「提供可执行的返修指导」。

通过现有 `{{ROLE_TABLE}}` 渲染，不引入独立职责追加句。已有方案拆解、合并验收、独立核验等职责继续使用原文。

### 2. 管理行为正文（AGENTS.md.tmpl）

路径 `templates/projects/<模板>/AGENTS.md.tmpl`，在完整角色章节之后插入「管理与协作责任」小节。插入点：software 在「开发流程」前；writing/research 在「工作流程」前；algorithm 在「研发流程」前；testing 在「测试依据」前；product-prototype 在「协作流程」前。

新增四条：

1. **保护整体效率**：优先解决影响后续交付的关键阻塞，协调交接等待和资源冲突，复用仍有效的验证证据。各角色对验收口径有分歧时，负责人先组织核对统一，再向执行成员给出一致要求。
2. **主动提供帮助**：收到求助或发现工作停滞时，负责人及时阅读现有成果与已尝试路径，复核自己的判断和要求，定位具体障碍。根据需要补充资料、验证关键接口、提供最小复现或可用样例、协调实际可用的权限资源、安排具名协助者，使成员清楚下一步怎样推进。技术路径或外部能力不确定时，组织最小验证，明确关键假设及继续推进或更换方案的判据，依据验证结果安排后续工作；验证结论附证据，尚待验证的判断明确标注。
3. **让返修能够执行**：返修发起者按审查交付要求逐项说明问题（位置、依据、预期与实际、影响），区分阻断项与改进建议，给出具体修复边界和与障碍匹配的帮助。复验步骤应能独立执行，写清前置条件、预期结果和通过判据；已有步骤可引用准确位置，命令或样例注明验证状态。缺少资料、权限或环境时，明确具体缺项、补齐责任人和下一动作。保留已通过成果，新增阻断说明新增证据或关联影响。
4. **跟踪帮助效果**：负责人检查支持措施是否解除障碍，效果不足时调整方法、协作安排或资源。成员及时报告尝试结果、困难和不确定性，负责人据此继续提供支持。同类问题反复发生时，将有效办法整理为可复用资料、工具或任务说明改进。

「返修发起者」指实际作出退回决定的审查或验收成员。具体帮助、执行责任及结果随实际环节记入原任务节点。

### 3. 审查要求去重补齐（AGENTS.md.tmpl）

问题位置、依据、预期与实际、影响集中维护在各模板既有审查段，已有同义要求视为覆盖，只补实际缺项，管理正文第 3 条引用，不重复列四项。落点：software「审查交付」；writing/research「工作流程」核验失败段；algorithm「评审与交付」；testing「评审与资源」；product-prototype「需求变更与评审标准」。software 将「预期与实际」补入逐项返修要求，并让问题与对应判断依据关联清楚。专业证据字段、task_log 调用及交接顺序保持原约定。

### 4. 重复返修话题触发（engine/wake.py）

`_WORK_SYSTEM_PROMPT` 第 5 条、`_CHAT_SYSTEM_PROMPT` 第 6 条，两处均只替换「L2 话题讨论」的括号内容为：

> 需多人讨论，或同一问题反复返修仍未解决时，建话题拉相关成员，结合已有证据和尝试记录明确原因、解决路径与协助分工→结论落库→收口

其余升级链保留。这是行为规范（成员据任务节点识别重复阻塞并发起），不是引擎自动触发。

## 范围外

工作群会话轮换、已关闭任务后缺陷另建修复需求、用户实测与关闭解耦三项继续单独讨论；阻塞自动检测（需阻塞原因结构化标识）、任务状态机、角色权限、既有项目 AGENTS.md 与人格/SOUL 配置迁移、无关重构均不实施。
