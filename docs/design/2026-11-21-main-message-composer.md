# 主消息输入框随内容伸缩

适用需求：#177。只调整 Web 主消息输入框的高度和文字区域滚动；不改行内回复、新建话题、项目助手、后端接口或现有按钮布局和发送规则。

## 依据

[主输入框样式](../../frontend/index.html#L350-L363)将文字区固定为 66 px 并隐藏溢出；[快捷键和发送回执](../../frontend/index.html#L3089-L3128)直接修改 `textarea.value`，不会触发普通 `input` 事件。隔离 Chrome 复现：三行后按 `Alt+回车`，内容滚动高度由 83 px 增至 103 px，可视高度仍为 64 px，滚动偏移仍为 7 px。新空行已进入排版高度，缺失的是可视区随内容伸缩，以及达到上限后对齐光标。

## 行为与实现边界

- 保留原生 `textarea`。高度按实际排版计算：自动折行、空行和末尾仅有光标的空行都算。不对用于计算高度的文本做 `trim`，不向真实草稿写入用于测量的占位字符。未封顶时随输入增高，删除或发送成功清空后重新测量并回缩；空框保留可编辑的最小高度。
- 上限随消息栏的实际可用高度调整。预算扣除固定标题和操作区，给聊天记录留可阅读、可滚动的空间；不能用「消息列表伸缩后的剩余高度」反推输入框高度而互相挤压。窗口缩放与栏宽变化后重新适配，不引入用户配置项。封顶后只滚动文字区，发送及附件按钮不随正文滚动。
- 保留 `回车` 发送、`Alt+回车` 换行以及现有点名和附件交互。真实换行与发送回执清空的两条程序写入路径都必须触发尺寸更新，不依赖浏览器自行派发 `input`。正文中插入换行后仅滚动必要距离，使当前光标行完整可见，不能直接滚到文末；不移动选区，也不抢聊天列表的滚动位置。
- 保留 [发送反馈与草稿契约](../engineering/MESSAGE-SEND.md#页面反馈)：回缩由实际草稿变化触发，不绕过目标与文本的清空判断，不影响失败保留、发送中防重和已关闭话题禁用。使用 [UI 规范](../ui-spec/UI-SPEC.md) 的主题与可达性约定，不照搬参考应用的外观和控件。

## 验收

| 场景 | 通过条件 |
| --- | --- |
| 空框连续换行、三行后再换行 | 对真实页面按 `Alt+回车`；每个新空行均计入排版高度，在未键入下一字时光标行已完整可见，且未发送消息。 |
| 长行自动折行、内容减少 | 自动折行每多占一行就参与高度计算；删除内容或当前目标发送成功后清空，输入框即时回缩；失败及迟到回执不改变原有草稿判定。 |
| 封顶后在正文中间换行 | 有足够的正文使文字区产生滚动，将光标移到正文中间且靠近当前可视区下沿，再按 `Alt+回车`。光标保留在本次插入处，新行完整进入文字可视区，后续正文仍可滚动到达，不跳到文末。 |
| 普通、窄屏和矮窗口 | 在普通桌面、390 px 窄屏以及 1280×480 的矮窗口验证，覆盖深浅主题。填充至封顶后，发送和附件按钮完整可见、聊天列表至少能完整显示一条单行短消息且可滚动；文字区滚动时按钮和聊天列表不一起滚。 |

复用 [测试索引](../../scripts/TEST_INDEX.md) 的隔离浏览器发送夹具与回归用例。光标验收同时取插入位置和行在文字可视区内的证据（可见光标截图或等价几何验证），不能只断言 `scrollHeight` 或文本末尾出现换行。实现交付同步 UI 规范和测试索引，测试报告记录被测提交和实际视口；不得发送生产消息。
