# 话题后台委派状态与助手待办幂等

## 话题展示需求

话题中的主 agent 等待子代理时，保留思考气泡，显示“子代理正在执行后台任务”。指示点保持静态，历史过程可展开，停止入口保持可用。主 agent 回调续跑后，同一逻辑执行恢复“思考中”；全部执行完成后沿用结束及折叠行为。页面刷新、断线恢复、长时间等待及嵌套委派均保留该状态。

DFS 发言顺序、发言位占用、调度互斥、执行归属、回调对账及停止协议沿用现有契约。工作会话的等待展示沿用现有行为。

## 展示实现

`/thinking` 将本地 `hermes_executions` 中 `kind=chat`、`state=waiting_delegation` 的记录合入展示快照，使用原 session、started_at、project、thread_id 标识。HTTP 状态读取只访问本地账本，状态读取产生零网关调用、零事件发布。调度内存结构和执行表保持原有更新方式。

话题网关执行的 `/reasoning` 返回本地 `execution_state`。逻辑执行活跃时，父轮 final 只结束原生轮次，内容条目的 `finished` 保持 false；逻辑执行终态与 `process_ended_at` 决定采集结束。回调沿用原游标与气泡身份。回复边界后的后台等待允许保留空内容气泡。

本功能覆盖引擎登记的活跃逻辑执行。已退出引擎执行生命周期的原生会话沿用现有可见性边界。

## 项目助手待办幂等

问题卡回答、提案确认或撤销会先移除对应待办。模型随后再次返回同一 `resolved_todo_ids` 时，将本会话历史中由服务端签发的 question/proposal ID 视为幂等完成。历史只提取 assistant/system 记录中的结构化卡片标识；用户文本、其他会话的卡片及未知 ID 保持校验拒绝。

当前待办按原规则逐项移除。历史卡片的重复关闭保持零配置写入、零其他卡片变更。使用持久历史核对身份，旧版本已发生的校验错误在重新检查时采用同一逻辑恢复。模型提示明确已回答的卡片由引擎处理，当前待办以本轮快照为准。

## 验收

- 隔离账本：话题等待快照、零网关查询、刷新恢复、父轮 final、原执行回调续接与终态清理；原发言位及跨话题调度回归。
- 前端生命周期：静默超时、回复后的空等待气泡、浏览器缓存、主 agent 恢复与逻辑结束。
- 合成 HTTP 与真实 Chrome：深浅主题、1280px 与 390px 消息列，静态指示点、标签、停止入口、刷新及嵌套等待。
- HUD：已回答卡片重复关闭、旧错误重试、其余待办保留、未知与跨会话 ID 拒绝。
