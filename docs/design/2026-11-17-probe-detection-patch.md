# 探针检测口径最小增补方案（2026-11-17）

## 背景

2026-11-17 14:33 复现发送卡顿（消息 11670：connect 1685.2ms、route 5148.2ms、total 6834.7ms）。现有探针唯一异常判据为 `connect_ms >= connect_threshold`（默认 5000），回放 11670 不触发——即使延长采集时段也会判「未复现」。现场证据见 reports/research/2026-11-12-morning-probe/INCIDENT-2026-11-17-11670.md。本方案基于 scripts/morning_send_probe.py 现状提出最小增补，供话题方案核定与审查。

## 增补点（最小范围）

1. 三阈值独立判定：connect_ms、route_ms、total_ms 分别设阈值（默认 5000 / 3000 / 5000，命令行可调，不硬编码），任一超限即记异常。
2. 记录触发原因：anomalies 记录增加 trigger 字段，列出每个触发项（字段名、实测值、阈值），保留原始全部字段；未触发的字段同样保留供事后分析。
3. 结论三态区分，落 exit 日志与报告：
   - 无发送样本：窗口内 send_count=0；
   - 有发送且未触阈值：send_count>0 且 anomaly_count=0；
   - 捕获慢请求：anomaly_count>0，附触发明细。
   三态以机器可解析枚举落盘（conclusion_enum: no_samples / samples_no_anomaly / anomaly_captured），中文文本仅作展示。废除仅按 connect 阈值判「未复现」的单一结论。
4. 回归用例四类（test_morning_send_probe.py）：
   - 11542（connect 19314.9 / route 3102.5 / total 22435.4）：三阈值全触发；
   - 11670（connect 1685.2 / route 5148.2 / total 6834.7）：connect 不触发、route 与 total 触发——验证新口径不漏报第二类样本；
   - 无发送样本：窗口内零发送，结论为 no_samples；
   - 阈值边界：字段值等于阈值时的判定语义（按现有 >= 实现，等于即触发）显式写用例锁定。
   既有两条结论断言随三态同步改造（旧断言与新枚举并存会导致套件红，改造与本增补同批提交）。
5. 触发阈值在运行时输出中回显（实际判定值），保证报告可复核。

## 范围外

- 全天常驻、持久定时调度：另行明确范围后处理；
- 引擎业务代码修改、生产重启：不在本增补内；
- 根因定位结论：本增补只改检测与记录口径，不改变「指标仅作关联线索」的边界。
