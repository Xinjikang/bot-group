# 协作与会话设计依据

系统以项目为中心组织群聊、话题、需求和任务。当前实现见 [工程约定](../engineering/ENGINEERING.md)，本页保留早期设计中仍适用的原则。

## 协作层次

执行中的问题由相关成员沟通；多方方案进入话题讨论；技术僵局交项目负责人协调；范围、优先级、费用与生产外部动作交用户决策。角色与权限决定具体交接人，重要结论写入需求、设计文档或任务节点。

任务阻塞记录业务原因和恢复条件，宿主命令审批按宿主权限机制处理。消息回复、任务节点和任务完成分别记录。

## 会话与上下文

会话按成员、项目和 work/chat 类型隔离，chat 进一步按话题隔离。同项目的 work 会话保留任务连续性，新话题拥有独立讨论上下文。持久知识由文档及任务记录承载。

引擎注入本次执行的项目、目录、身份和动态任务信息，项目约定由分配工作区的 AGENTS.md 提供。工作区与会话绑定见 [项目配置](../engineering/PROJECT-CONFIGURATION.md) 和 [命令与会话](SLASH-COMMAND-DESIGN-2026-09-27.md)。

## 状态与隔离

运行、心跳、回复和消息已读状态各有含义。思考状态按项目、话题及执行归属展示，退出和重启恢复核对真实执行记录。群聊、话题和任务列表按项目范围查询，成员资格和操作权限在服务端校验。

多项目数据在统一数据库中保存，以稳定项目身份关联。项目切换更新视图与提交上下文，目录变更保留既有任务的来源记录。现行契约见 [项目入口](../engineering/REQ101-PROJECT-ENTRY-2026-10-10.md) 和 [访问控制](../engineering/ACCESS-CONTROL.md)。
