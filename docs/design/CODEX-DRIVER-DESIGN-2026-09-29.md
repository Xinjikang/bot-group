# Codex 驱动与 Bot 身份设计

## 对象分层

| 对象 | 职责 |
| --- | --- |
| 宿主 Profile | 运行环境、模型、认证及宿主配置 |
| Bot | 引擎内稳定身份，绑定 runtime、配置根目录与 profile |
| 项目成员 | Bot 在项目内的角色、权限、启停、工作目录和会话关系 |

自动发现提供候选资源，用户选择后注册或复用 Bot，再加入指定项目。显示名由 Bot 统一维护，项目角色与授权独立管理。数据唯一性、失效资源和迁移行为以 [项目配置](../engineering/PROJECT-CONFIGURATION.md) 为准。

## 执行与会话

Codex 与 Hermes 使用各自的原生执行入口，通用队列负责项目隔离、忙闲、心跳、退出与重试。Codex 原生 thread ID 由执行事件捕获并持久化，恢复使用已确认映射；命令入口、generation 和恢复失败见 [命令与会话](SLASH-COMMAND-DESIGN-2026-09-27.md)。

执行记录保存 runtime 及原生会话身份，避免把某一宿主专用字段扩展为含义不清的通用字段。停止和恢复以当前执行记录为依据，完成消息依据有效身份进行校验。

## 工具与授权

两个宿主按同一项目权限及执行模式使用工具。chat/work 限制、拆解授权、签名凭据和项目范围遵循 [访问控制](../engineering/ACCESS-CONTROL.md)。工作目录与主目录报告授权通过明确入组或工作区配置建立，详见 [Codex 配置目录](../guides/CODEX-PROFILE-HOMES.md)。

## 冷启动与验证

内置用户身份、Bot 注册和项目入组分别管理；首次打开可发现宿主候选，空项目保持空成员及授权，后续配置保持可追溯性。

验证注册复用、跨项目入组、角色与权限、工作目录、会话创建恢复、退出与停止、首次安装及缺失宿主。宿主 CLI 事件和真实模型行为分别保留证据，测试报告与源码分开存放。
