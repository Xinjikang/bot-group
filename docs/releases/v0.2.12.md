# v0.2.12 — 2026-11-09

本版本补齐 Hermes MCP 初始化失败的诊断与一次受限恢复，减少消息发送的数据库提交次数，并改善发送期间的界面反馈。

## 修复

- 保留网关回执中的原始错误，经脱敏后写入执行账本和日志；接入日志增加连接、会话绑定、MCP 配置及业务提交阶段耗时。
- MCP 初始化失败且权威回执确认模型与工具均未执行时，自动重试一次。恢复沿用原唤醒作业 ID、入队时间与队列顺序；停止、话题换轮、成员或项目状态变化继续受保护。重试前重新确认任务工具连接可用。
- 消息、收件箱、话题状态和唤醒入队统一为一次事务提交，入队异常时整笔回滚。SQLite 持久性设置、队列去重及 DFS 发言顺序保持原样。
- 主输入框立即显示“发送中…”，阻止同一目标重复提交。失败保留草稿，成功时保护切换目标或发送期间的新输入；增加连接、写锁、消息处理、入队、提交和事件发布耗时日志。
- 修正混合运行时 busy 回归夹具缺少 DSH 生产命令 `--json` 参数的问题。该项属于测试身份模拟修正，生产调度器沿用原有实现。

实现与约束见 [MCP 初始化恢复](../design/2026-11-06-mcp-startup-recovery.md)、[发送延迟设计](../design/2026-11-06-message-send-latency.md) 和 [消息发送契约](../engineering/MESSAGE-SEND.md)。

## 验证边界

本次发布范围隔离回归 185 项、发布专项 44 项通过；真实 Chrome 的深浅主题 × 1280/390px 共 4 组通过，4 个 Node 前端回归模块通过。混合运行时 busy 模块全部通过，先前失败的夹具用例已恢复有效验证。

隔离回归覆盖原始错误脱敏、零执行恢复门禁、一次重试预算、原作业和顺序保护、消息原子提交、回滚、去重及运行流量。合成 HTTP 的真实 Chrome 验证覆盖深浅主题及桌面、窄屏发送状态和草稿保护。发布资产、安装、升级恢复和 BAT 入口按发布指南验证。

旧、新路由在同一临时数据库副本交错执行各 40 次，发送中位数约 9.0→6.4 ms，P95 约 86.8→77.4 ms，提交次数 2→1。偶发磁盘提交尖峰继续保留；现场端到端耗时和真实网关恢复效果需结合升级后的阶段日志核验。

Hermes 源码保持独立，本版本通过官方网关接口适配。MCP 恢复采用合成权威回执验证；真实模型执行与生产网关故障注入另行验收。

## 升级

Release 安装使用“设置 → 关于 → 检查新版本”或 `upgrade.bat`。Git 源码安装更新后手动重启引擎并刷新页面。

发布资产包含源码 ZIP、`release_manifest.json`、`SHA256SUMS`、`releases.json`、`bootstrap.py` 和 `install.ps1`；操作步骤见 [发布指南](../guides/RELEASE-GUIDE.md)。
