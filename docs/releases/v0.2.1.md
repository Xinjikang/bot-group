# v0.2.1 — 2026-10-29

本版本完善项目助手引导、升级操作反馈，以及 macOS/Linux 安装和运行维护的兼容性。

## 项目助手

- 为 Hermes 网关、旧版 CLI 和 Codex 分别注入专用系统指令，结合实际项目目录、文档和配置进行引导。
- 检查 Git 仓库范围、远程配置、工作区修改、CodeGraph 代码索引、文档链接及成员和资源配置；失败或未覆盖的检查明确保留待核实状态。
- 配置建议按“当前内容 / 建议改为”展示，说明保存位置；项目备注单独展示使用范围。建议经用户确认后生效。
- 使用日常语言解释配置影响，按开发、提交、测试和交付阶段提醒所需准备。

## 升级反馈

- 确认升级后立即显示提交进度，等待期间防止重复提交。
- 提交失败时弹窗提示，并在窗口保留 HTTP 状态码、请求地址和服务返回的原因；通用 500 错误显示中文说明。
- 查询进度失败显示具体错误并自动重试；响应丢失时继续核对已保存的升级请求。

## 跨平台兼容

- pywin32 仅在 Windows 安装和校验；安装与 repair 在目标解释器中求值环境标记并核对锁定版本。
- 旧版 Hermes CLI 的临时数据目录保持所选运行环境，依赖导入失败提示修复运行环境，其他子进程错误显示退出码。
- 识别 POSIX Python/Hermes 进程名，补齐进程树清理，并保留 profile/session 范围及引擎宿主保护。
- macOS 使用原生目录选择窗口；Linux 使用 tkinter，需要本机图形桌面和相应组件，窗口不可用时可手动输入路径。
- 新增 `upgrade.sh`，补齐 shell 入口执行位、LF 换行和源码 ZIP 的执行权限。
- 修正 README：默认数据库位于 `data/group.db`，日志位于安装目录下的 `logs/`。

## 验证范围与升级

相关回归覆盖 Windows 真实进程树、隔离 Bash 升级入口及跨平台分支模拟。macOS 原生目录窗口、整机安装和报告者 Hermes 环境仍需对应机器复验。升级反馈修复提供明确诊断信息；issue #15 现场 HTTP 500 的服务端根因仍待日志确认。

Release 安装可通过“设置 → 关于 → 检查新版本”升级；Windows 也可运行 `upgrade.bat`，macOS/Linux 使用 `./upgrade.sh`。尚无该脚本的旧安装可运行基础 Python 的 `tools/upgrade.py upgrade`。命令行升级后使用启动入口恢复服务。Git 源码安装更新后运行 `tools/install.py repair` 并手动重启引擎。

安装与恢复步骤见[发布指南](../guides/RELEASE-GUIDE.md)。本次提供源码 ZIP、`release_manifest.json`、`SHA256SUMS`、`releases.json`、`bootstrap.py` 和 `install.ps1` 六项资产。
