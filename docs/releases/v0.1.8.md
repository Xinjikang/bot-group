# v0.1.8 — 2026-10-28

本版本修复 v0.1.7 中旧版 Hermes CLI 的执行鉴权回归。使用旧版 Hermes 的用户应及时升级引擎。

## 修复内容

旧版 Hermes 启动成功后，其心跳、收件箱、群聊回复和任务工具可能返回 `401 Execution credential expired or unregistered`。消息持续待处理会触发重复唤醒，成员可能反复分析同一错误。

HTTP 鉴权现已接受当前签名代次下的有效 Hermes CLI 执行。校验继续绑定成员、项目、话题、会话和启动时间；执行结束、记录缺失、身份不匹配及旧代凭据仍被拒绝。Codex 本地执行与 Hermes 网关的鉴权、终态撤销和跨引擎重启契约保持原有行为。

## 升级与恢复

- Release 安装：通过“设置 → 关于”或 `upgrade.bat` 升级到 v0.1.8，完成引擎重启。
- Git 源码安装：更新到本版本，执行 `tools/install.py repair`，再手动重启引擎。
- 鉴权恢复后，成员若仍反复沿用旧的错误判断，可在成员菜单重置工作会话，或发送 `@成员 /new`，然后重新发送需要处理的消息。会话重置保留历史记录。

本补丁沿用既有数据格式与签名文件，无新增数据库迁移。升级时保留实例数据及匹配的 `secrets/bot-signing.key`，使用标准升级流程完成备份与恢复检查。

## Hermes 支持与验证

旧版 CLI 会话兼容基线为 0.21.1、0.21.3；本次补充实际 Hermes 0.21.3 的配置加载验证，以及持久签名下真实 stdio MCP 的读取、回复、确认已读和终态撤销验证。网关路径沿用 v0.1.7 的 Hermes 0.22.5 验证范围；其他构建按实际接口与协议能力检查。

修复相关 133 项回归通过，真实 MCP 闭环通过：心跳和消息操作返回 200，回复确认后收件箱清空，结束后凭据返回 401。隔离扫描回归确认已处理消息停止重投。模型推理行为与用户历史上下文恢复需在升级后核对实际回复。

发布资产包含源码 ZIP、`release_manifest.json`、`SHA256SUMS`、`releases.json`、`bootstrap.py` 和 `install.ps1`。安装、升级及源码清单验证方法见 [测试索引](../../scripts/TEST_INDEX.md)。
