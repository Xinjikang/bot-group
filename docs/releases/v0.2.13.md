# v0.2.13 — 2026-11-09

本版本修复旧版 Hermes 已有会话绑定被送入新版网关状态检查、导致群聊持续排队的问题，对应 [Issue #28](https://github.com/Xinjikang/bot-group/issues/28)。

## 修复

- 唤醒前的原生状态预检查复用执行入口的能力分流。旧版 Hermes CLI 沿用按 profile 和会话身份匹配的进程检查，保留空闲、忙碌和未知三态；分流先于原生查询缓存和网关连接。
- 会话切换、未结束执行和待清理状态继续保护执行归属；网关版继续查询原生 running/pending，查询故障继续暂缓对应会话。
- 补充旧版已有绑定、进程退出恢复、原话题队列恢复及网关故障保护回归。原生测试夹具显式提供网关源码布局，Windows 启动器验证显式使用临时 home。

实现与约束见 [旧版状态分流](../design/2026-11-09-hermes-legacy-state-routing.md) 和 [兼容契约](../engineering/HERMES-COMPATIBILITY.md)。

## 验证边界

修复相关隔离回归 121 项通过，发布专项 34 项通过。覆盖旧版进程检查、原作业 ID 与入队时间保留、绑定与话题发言位保留、网关 busy 与失败暂缓、执行账本、换证、Windows 真实临时进程查询、源码资产、安装、升级恢复和 BAT 字节一致性。

Hermes `d923a5eb487a17c0a68801bba9ef0f56c81040a8` 已静态核对，缺少新版网关识别文件，其 identify 响应缺少新版要求的 ready 状态。本轮通过临时源码布局和模拟 RPC 验证分流，真实 v0.22.2 模型与 MCP 完整回复链路及问题报告者现场恢复需在对应运行环境核验。网关版已有实测基线为 Hermes v0.22.5 / `bf0203a7`，其他构建按实际接口与运行证据确认。

## 升级与话题恢复

Release 安装使用“设置 → 关于 → 检查新版本”或 `upgrade.bat`。Git 源码安装更新后手动重启引擎并刷新页面。

修复生效后，仍有效的 `queued` 作业由正常调度继续投递，沿用原 ID、入队时间、会话、绑定代次与话题发言位。CLI 仍在运行或进程状态未知时继续等待；话题关闭、换轮或成员停用继续遵循既有有效性检查。

发布资产包含源码 ZIP、`release_manifest.json`、`SHA256SUMS`、`releases.json`、`bootstrap.py` 和 `install.ps1`，安装步骤见 [发布指南](../guides/RELEASE-GUIDE.md)。
