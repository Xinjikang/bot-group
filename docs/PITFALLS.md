# 维护经验

本页保留早期工程记录中仍适用的故障边界。现行架构以 [工程约定](engineering/ENGINEERING.md) 及其专题为准，执行结果保存在项目主目录测试报告。

## 调度与并发

- 消息去重、回复关联与会话绑定包含项目、话题和执行身份。跨话题共用项目级去重键会遗漏应处理的消息。
- 领取发言权、领取任务和推进状态应在事务内校验并更新，避免扫描器与队列并发领取。
- 判断话题收口时同时检查活跃执行、心跳与未读状态。自然语言中的短回复或 pass 应通过明确的协议状态处理，避免互相触发唤醒。
- 恢复任务、重启服务或返修后，核对当前 revision 与有效执行记录；旧运行结果和旧 revision 重试不得覆盖当前状态。
- 停用成员与调整角色需要按项目作用域生效，并同步影响当前话题与后续调度。

参见 [消息执行](engineering/BOT-MESSAGE-EXECUTION.md)、[消息注入](design/MESSAGE-INJECTION-DESIGN-2026-09-27.md)、[拆解授权](engineering/REQ99-DECOMPOSITION-GATE-2026-10-08.md)。

## 消息、任务与宿主边界

- work/chat 执行身份决定工具可用范围；身份解析失败应明确报错。回复门禁使用消息 ID 和项目范围，按接收者计算是否需要回复。
- 运行状态、思考动画与会话记录采用各自的生命周期；回复到达后及时停止对应执行的动画。
- 会话恢复和宿主退出需检查已登记的进程及父子关系，进程名匹配范围过大会误停其他会话。
- 多行参数、中文与长上下文应核验宿主实际收到的内容，测试覆盖转义和命令行长度限制。

参见 [任务交接](engineering/TASK-BRIEF-CONTRACT.md)、[命令与会话](design/SLASH-COMMAND-DESIGN-2026-09-27.md)、[Hermes 参数传输](engineering/HERMES-ARGUMENT-TRANSPORT-2026-10-17.md)。

## 前端与生命周期

- 局部刷新同时保持选区、展开状态和固定操作按钮的位置，长列表使用明确的滚动容器。
- 页面重载后核验服务端状态和资源版本；仅验证当前页面的内存状态容易漏掉恢复问题。
- 服务停机与升级核对程序目录、数据库和实例身份；隔离测试只允许操作自身创建的资源。
- 前端关闭状态与后端停止状态分别验证，重启回执应支持跨进程刷新和新实例健康确认。

参见 [固定面板控件](engineering/FIXED-PANEL-CONTROLS.md)、[前端刷新](engineering/FRONTEND-REFRESH.md)、[停机隔离](engineering/SHUTDOWN-ISOLATION-FIX-2026-10-17.md)、[服务重启](engineering/SERVICE-RESTART-2026-10-17.md)。
